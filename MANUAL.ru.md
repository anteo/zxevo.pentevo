# Документация разработчика ZX Evolution

[English version](MANUAL.en.md)

Это справочник программиста **ZX Evolution / PentEvo**, организованный по подсистемам, которые
расширяют или изменяют ZX Spectrum 48K. Он охватывает унаследованную модель программирования ATM
Turbo 2+, собственные аппаратные расширения Evolution и сервисы ПЗУ. Обычные инструкции Z80, BASIC и
неизменённые вызовы ПЗУ Spectrum 48K здесь не повторяются.

Аппаратная часть справочника опирается на BASECONF FE из `a3daae83`, прежде всего на
[`fpga/base_trdemu/trunk`](fpga/base_trdemu/trunk/) и [`avr/baseconf/trunk`](avr/baseconf/trunk/).
Контракты ROM/RST учитывают исправления ПЗУ в этом форке. В [`rom/version.a80`](rom/version.a80)
по-прежнему объявлены ERS **0.61.01** и DOS **0.60**, поэтому две сборки с одинаковым номером
ERS могут вести себя по-разному. Для проверки конкретной платы учитывайте, из каких исходников
собраны её образы AVR/FPGA и ПЗУ.

## Как читать справочник

Предполагается знакомство с командами Z80 и устройством Spectrum 48K. Выберите раздел по задаче.

- Для программы на C начните с настройки z88dk и примеров `lib/baseconf`. Там же описан запуск
  тестов в ZEsarUX. [README библиотеки BaseConf](lib/baseconf/README.ru.md)
- Для прямой работы с аппаратурой сначала определите, в каком режиме доступен порт, и какие
  страницы видит CPU. [Указатель портов](#ports) · [Карты памяти](#memory)
- Для вызовов ПЗУ начните с требований к окну 0 и соглашения о параметрах. Для дисков и файлов
  описан порядок выбора тома. [ROM/RST API](#rst-api) · [Устройства, FAT и образы](#rst-storage)

Основные обозначения в справочнике приведены ниже.

- **CPU** — процессор Z80, исполняющий программу. **FPGA** — программируемая логическая микросхема,
  реализующая память, видео и большую часть портов. **AVR** — микроконтроллер ATmega128,
  обслуживающий периферию.
- **Регистр устройства** — байт настроек или состояния, доступный через порт. Это не обязательно
  регистр самого Z80. **API** — набор программных вызовов с определёнными параметрами и
  результатами. **ERS** — EVO Reset Service, сервисное ПО в ПЗУ.
- **Порт** — адрес ввода-вывода для команд `IN`/`OUT`. Он не относится к адресному пространству
  памяти для `LD`. **Банк/страница памяти** — физический блок RAM или ROM; **окно** — область
  адресов CPU, куда этот блок включён.
- **Активный ноль** означает, что значение 0 обозначает действие или нажатие; при активной единице
  это значение 1. Суффикс `_n` в именах сигналов обычно указывает на активный ноль.
- **WAIT** — сигнал, заставляющий CPU ждать окончания обращения. **Contention** — дополнительные
  задержки при доступе CPU к памяти/портам во время работы видеоконтроллера. **M1** — цикл выборки
  опкода Z80; его часть refresh предназначена для регенерации динамической памяти.
- `BF.3` означает бит 3 регистра порта `xxBF`; биты нумеруются с нуля. `D7:0` — биты данных,
  `A15:A8` — старший байт адреса. `0xFF` и `FFh` обозначают одно шестнадцатеричное число. В формулах
  `&`, `|`, `~` — побитовые AND, OR и инверсия; `<<`/`>>` — сдвиги; `{...}` объединяет перечисленные
  биты слева направо, от старшего к младшему. Например, `{D6,D2:0}` — четыре бита в порядке
  D6,D2,D1,D0. `||` означает логическое «или».

## 2. Правила ввода-вывода и полный указатель портов

<a id="shadow-mode"></a>

### 2.1 Обозначения, дешифрация и теневой режим

Адреса в таблицах портов шестнадцатеричные. `xxFE` обозначает адреса с младшим байтом FE; старший
байт может быть любым, **если ниже его разрядам явно не назначена функция**. В шаблонах наподобие
`xFF7` каждая `x` обозначает одну неуказанную шестнадцатеричную цифру; допустимые конкретные адреса
перечислены рядом.

`R` означает чтение, `W` — запись, `RW` — оба вида доступа. Таблица описывает поддерживаемые
операции: наличие электрического ответа при другой операции не означает, что у него есть
определённый программный смысл. Используйте перечисленные 16-битные адреса. Из-за неполной
дешифрации устройство иногда отвечает и по другим адресам, но такие дополнительные адреса могут
измениться в другой версии FPGA.

В отличие от ULA 48K, произвольный чётный порт не обязательно является портом бордюра/клавиатуры.
Есть намеренные исключения: `xxF6` и `xxFC` описаны ниже. Если старший байт важен, используйте
`LD BC,port` и `IN A,(C)` / `OUT (C),A`. У `IN A,(n)` и `OUT (n),A` старший байт адреса
равен значению A **до** выполнения команды. Блочный ввод-вывод меняет B между обращениями,
что существенно для теневого интерфейса SD.

FPGA считает теневой режим включённым, если активен внутренний сигнал DOS или установлен бит 0 порта
BF:

```text
shadow = DOS || BF.bit0
```

DOS здесь — аппаратное состояние, управляющее доступом к портам и выбором страниц. Оно не означает,
что программа прямо сейчас выполняет дисковую команду.

«Теневые порты» — второй набор регистров ввода-вывода, доступный только в этом специальном
состоянии. Например, чтение `1Fh` в обычном режиме опрашивает джойстик, а в теневом — состояние
контроллера дисковода. Это не скрытая память: один адрес ввода-вывода получает разную дешифрацию в
зависимости от состояния компьютера. Перед обращением приложение должно обеспечить нужный режим.

`BF.0` принудительно открывает теневые порты, не включая ПЗУ DOS. Сброс этого бита не закрывает их,
если DOS остаётся активным. DOS можно принудительно удерживать включённым, записав `xx77` с A9=0.
Другой способ входа — выборка опкода из ПЗУ по смещению `3Dxx` при настройках диспетчера, описанных
в §3.4. Отображение памяти и доступность теневых портов связаны, но это разные состояния.

Для обычных `EFF7`, `DFF7`, `BFF7` нужны `DOS=0` и `BF.0=0`. В теневом режиме последние два адреса
записывают регистры диспетчера ATM; для RTC используйте `DEF7` / `BEF7`. `EEF7` в этих исходниках
**не является** теневым аналогом `EFF7`.

### 2.3 Приоритет ZXBUS и чтение незанятых портов

Когда Z80 выполняет `IN` или `OUT`, FPGA определяет по адресу порта и текущему режиму компьютера,
предназначено ли обращение встроенному устройству. Если адрес распознан как встроенный порт, FPGA не
передаёт сигнал обращения `IORQ` на слоты ZXBUS. Поэтому плата расширения в слоте не получает это
обращение через стандартный интерфейс шины. Например, при обращении к IDE по совпадающему адресу
управление остаётся у встроенного контроллера. Такой же приоритет имеют встроенные порты клавиатуры,
SD и мыши.

Для обращений, которые FPGA передала на ZXBUS, действует приоритет слотов: плата в первом слоте
может сигналом `IORQGE` запретить передачу `IORQ` во второй слот. Таким образом, порядок
обслуживания — встроенные устройства, затем первый слот, затем второй.

FPGA иногда распознаёт целую группу адресов по младшему байту, хотя не все значения старшего байта
соответствуют реализованным регистрам. Например, в базовой реализации все адреса `xxBD` блокируются
для ZXBUS, включая адреса без реализованного регистра. Плата расширения не может использовать такие
адреса через стандартный интерфейс шины.

Отдельный случай — Covox: FPGA обрабатывает запись в `xxFB`, но этот адрес не включён в условие
блокировки ZXBUS (`porthit`). Поэтому сигнал обращения к этому порту может поступить также на платы
расширения.

При чтении порта, который не обслуживает ни встроенное устройство, ни плата расширения, CPU получает
`FF`. В базовой реализации `FF` выдаётся и при подтверждении прерывания. Это отличается от floating
bus оригинального 48K. Неопределённое чтение неописанного регистра `xxBD` не позволяет надёжно
определить, какие расширения поддерживает установленная FPGA.

Источники: [`zports.v`](fpga/base_trdemu/trunk/z80/zports.v),
[`zbus.v`](fpga/base_trdemu/trunk/z80/zbus.v), [`top.v`](fpga/base_trdemu/trunk/top.v).

## 3. Память, диспетчер страниц, ПЗУ и Flash

### 3.1 Физические страницы и константы исходников ПЗУ

Адресное пространство Z80 разделено на четыре области по 16 КиБ, называемые окнами: 0=`0000–3FFF`,
1=`4000–7FFF`, 2=`8000–BFFF`, 3=`C000–FFFF`. Диспетчер страниц выбирает, какой физический блок RAM
или ROM виден CPU в каждом окне. Полный набор настроек всех четырёх окон называется картой памяти.

FPGA хранит две карты памяти, с номерами 0 и 1. Программа может заранее настроить их по-разному, а
затем переключаться между ними. В каждый момент CPU использует только одну карту — активную. При
переключении карты сразу применяются её настройки для всех четырёх окон. Как программа выбирает
активную карту, описано в §3.5.

ОЗУ содержит 256 физических страниц, Flash — 32 физических банка.

В библиотеке C функции отображения окон принимают физические номера RAM `0..255`.
Пул `bc_ram_page_pool_t` и банковая куча поверх него охватывают страницы `0..63`, по одному
биту на страницу в восьмибайтовой маске. [memory.h](lib/baseconf/include/baseconf/memory.h)

Номер страницы, записываемый в порты ATM/Evolution, инверсный. Различайте:

| Обозначение                        | Значение                                                                                 | Пример                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Физическая страница RAM            | Номер в линейной DRAM, `0..FF`                                                           | Подстановка NMI — физическая `FF`                                        |
| Константа RAM ERS в исходниках ПЗУ | Число, которое код передаёт как байт данных селектора `x7F7`; `FF - физическая_страница` | `RAM_NMI=00` выбирает физическую `FF`; `RAM_EVODOS=01` — физическую `FE` |
| Константа ROM ERS                  | Значение для `xFF7` с дополнительными битами типа/управления                             | `ROM_ERS=0` выбирает последний банк Flash; `ROM_RST83=9` — банк `16h`    |

`RAM_NMI` — символ-константа, объявленный через `SETVAR` в `rom/global_vars.a80`. Он имеет значение
`00h`; код ERS использует его как данные при выборе страницы RAM. Адрес порта задаётся отдельно. При
записи значения `00h` в селектор `x7F7` из-за инверсной нумерации выбирается физическая RAM-страница
`FF`.

Для константы ROM `r=00h..1Fh` физический банк Flash равен `1Fh-r`; смещение его блока в линейном
образе — `(1Fh-r)*4000h`. Поэтому сервисная страница находится в **конце** 512-КиБ образа.

Номера RAM и Flash относятся к разным областям памяти. `RAM_NMI=00` — константа RAM: она выбирает
физическую страницу DRAM `FF`, где расположены обработчик NMI/RST и рабочие данные ERS. `ROM_ERS=00`
— константа ROM: она выбирает банк Flash `1F`, содержащий страницу reset service. Каталог исходников
`rom/page0` соответствует ROM-слоту `ROM_ERS`; физическая RAM-страница `00` — другая страница DRAM.

В аппаратных разделах номера страниц далее **физические**, если явно не сказано, что это значение
порта или константа ERS.

<a id="bf-control"></a>

### 3.2 `xxBF`: конфигурация Evolution

Порт `xxBF` доступен и в обычном, и в теневом режиме. Запись задаёт сразу все перечисленные ниже
биты; чтение возвращает сохранённые настройки.

| Бит | Действие                                                                                           | После аппаратного сброса          |
| --- | -------------------------------------------------------------------------------------------------- | --------------------------------- |
| 0   | 1 открывает теневые порты, не переключая ROM на TR-DOS                                             | 0                                 |
| 1   | 1 разрешает CPU передавать записи в микросхему Flash; 0 запрещает                                  | 0                                 |
| 2   | 1 включает запись копии каждого записываемого CPU байта в память шрифта                            | 0                                 |
| 3   | Переход **1→0** запрашивает NMI; сама запись 1 прерывание не вызывает                              | 0                                 |
| 4   | 1 включает сравнение адреса выбираемого опкода с заданным адресом ловушки; совпадение вызывает NMI | 0                                 |
| 5   | 1 выбирает формат палитры с четырьмя битами на компоненту R, G, B; 0 — с двумя                     | 0                                 |
| 7:6 | Резерв; записывать нули                                                                            | В этих исходниках читаются нулями |

**Бит 0 — доступ к теневым портам.** Он позволяет обращаться к регистрам диспетчера ATM, контроллера
дисководов и другим теневым портам, даже если программа исполняется из RAM и не входила в TR-DOS.
При сбросе бита обычный режим вернётся только тогда, когда аппаратный сигнал DOS тоже выключен.
Подробнее: [обычный и теневой режимы портов](#shadow-mode).

**Бит 1 — разрешение записи Flash.** Если в окно CPU включён банк Flash, обычные записи в эту
область при BF.1=0 до микросхемы не доходят. BF.1=1 снимает этот общий запрет, но защита от записи
конкретного окна продолжает действовать. Бит не стирает Flash и не записывает в неё данные сам:
программа должна выполнить команды программирования, предусмотренные микросхемой. Подробнее:
[программирование Flash](#flash-programming).

**Бит 2 — загрузка шрифта.** Пока он равен 1, каждая запись CPU в память одновременно записывает тот
же байт в ОЗУ шрифта по адресу `адрес_CPU & 07FFh`. Например, запись в RAM по адресу 8000h также
изменит байт шрифта по адресу 000h. Исходная запись в RAM тоже выполняется. Поэтому даже запись
адреса возврата на стек при прерывании может испортить шрифт; включать этот бит следует только на
время загрузки. Подробнее: [устройство ОЗУ шрифта и порядок загрузки](#font-ram).

**Бит 3 — программный запрос NMI.** Установите BF.3 в 1, затем сбросьте в 0, сохранив остальные
настройки BF. FPGA запомнит спад и подаст немаскируемое прерывание Z80 в начале следующего
кадрового прерывания. Подробнее: [вход в NMI и подстановка страницы обработчика](#nmi-entry).

**Бит 4 — запрос NMI по адресу команды.** Адрес задаётся двумя байтами: младший записывается в порт
10BD, старший — в 11BD. При BF.4=1 FPGA сравнивает с ним адрес, по которому CPU выбирает опкод.
Совпадение немедленно запрашивает NMI. Чтение или запись данных по этому адресу ловушку не вызывает.
Подробнее: [настройка запроса NMI по адресу команды](#execution-breakpoint).

**Бит 5 — точность компонентов палитры.** В обычном формате каждая компонента R, G и B имеет два
бита: можно выбрать 64 сочетания цвета. В RGB444 каждой компоненте отведено четыре бита: доступны
4096 сочетаний. Число элементов палитры ATM при этом остаётся равным 16. Сам бит не загружает новую
палитру: он меняет формат записи цветов через xxFF и обработку расширенного цвета. Подробнее:
[формат RGB444, адресные биты цвета и ограничения вывода](#rgb444).

Все реализованные поля в этой версии читаются обратно. Сохраняйте остальные биты при изменении
одного: запись `01` для открытия теневых портов одновременно выключает запись Flash/шрифта, ловушку
и расширенный цвет. Сброс бита 3 при последовательности «прочитать BF → изменить биты → записать BF»
запросит NMI, если прежнее значение этого бита было 1.

### 3.3 `xx77`: системный порт ATM

Для записи в `xx77` нужны два условия: уже открыты теневые порты, а младший байт адреса равен `77`.
В команде `OUT (C),A` адрес порта находится в `BC`, а данные для записи — в `A`. Поэтому в `FD77`
буквы `FD` — старший байт **адреса**, а `77` — младший байт адреса. Ни один из них не является
байтом данных.

FPGA использует разные части этой операции отдельно:

- В **старшем байте адреса** `FD` важны A14, A9 и A8. Здесь A9=0 удерживает аппаратное состояние
  DOS, A8=1 оставляет диспетчер памяти включённым, A14=1 запрещает запись палитры через `xxFF`.
  Остальные адресные биты в этой функции не задают режим.
- В **байте данных**, который программа помещает в `A`, D2:D0 выбирают видеорежим, а D3 — частоту 14
  МГц. D7:D4 этим регистром не используются.

Например, `OUT` в порт `FD77` со значением `03` задаёт ZX-видеорежим (D2:D0=3), выбирает 7 или 3,5
МГц по `EFF7.4` (D3=0), удерживает состояние DOS (адресный A9=0), оставляет диспетчер включённым
(A8=1) и запрещает запись палитры (A14=1). Значение `03` — **байт данных**, а `FD77` — **адрес
порта**. Это значение данных не является содержимым видеопамяти.

```asm
        ld bc,0xFD77      ; адрес: A9=0 держит DOS, A8=1 включает диспетчер
        ld a,0x03         ; данные: D2:D0=3, ZX-видеорежим; D3=0
        out (c),a
```

`BF.0` и A9 в адресе `xx77` не дублируют друг друга. `BF.0=1` принудительно открывает теневые порты,
не меняя само состояние DOS; это удобно, когда нужно настраивать диспетчер из программы в RAM.
Адресный A9=0 удерживает само состояние DOS включённым. Поэтому очистка `BF.0` не закрывает теневые
порты, пока DOS удерживается через A9. И наоборот, A9=1 разрешает обычный автоматический вход и
выход DOS, но `BF.0=1` всё равно держит теневые порты открытыми. A9 сам по себе не выбирает DOS-ПЗУ:
отображение ROM задаётся настройкой окна и правилами диспетчера ниже.

Ниже приведены канонические адреса, сохраняющие A8=1 (диспетчер включён). В столбце про палитру
указано действие A14. Столбец про DOS описывает A9: «удержание» означает A9=0, «автоматический
режим» — A9=1.

| Адрес порта | A9 / состояние DOS                 | A14 / запись палитры |
| ----------- | ---------------------------------- | -------------------- |
| `FD77`      | A9=0, удерживать DOS               | A14=1, запрещена     |
| `BD77`      | A9=0, удерживать DOS               | A14=0, разрешена     |
| `BF77`      | A9=1, обычный автоматический режим | A14=0, разрешена     |
| `FF77`      | A9=1, обычный автоматический режим | A14=1, запрещена     |

Для выключения диспетчера сбросьте A8 в адресе. `FC77` сбрасывает A8, `FD77` оставляет его
установленным. Управляющий **адрес порта** задаётся отдельно от значения данных в `A`. При каждом
изменении данных сохраняйте нужные D2:D0 (режим видео) и D3 (частота 14 МГц), иначе изменится и этот
параметр. Подробности: [карты памяти](#window-mapping), [видеорежимы](#video-modes),
[палитра](#atm-palette).

После аппаратного сброса диспетчер выключен, DOS удерживается, видеорежим 3, 14 МГц выключены. Перед
включением диспетчера стартовая программа ПЗУ должна настроить обе карты. Аппаратный сброс сам по
себе не устанавливает все номера страниц, типы RAM/ROM и правила подстановки в состояние, пригодное
для работы.

### 3.4 Отображение окна

Адреса `0000–FFFF` разделены на четыре окна по 16 КиБ. Процессор видит только текущую карту из
четырёх окон; карта выбирается битом `7FFD.4` (§3.5). Запись в один из портов ниже меняет настройку
одного окна активной карты. Две карты хранят настройки раздельно.

У каждой строки таблицы три адреса, потому что каждый из них меняет свою настройку окна. `x` — одна
шестнадцатеричная цифра, определяемая номером окна; адреса уже приведены для всех четырёх окон.
Например, для окна 3 (`C000–FFFF`) это `FFF7`, `F7F7` и `FBF7`.

| Окно CPU       | Задать тип и базовый номер | Задать полный номер RAM | Защитить от записи |
| -------------- | -------------------------- | ----------------------- | ------------------ |
| 0: `0000–3FFF` | `3FF7`                     | `37F7`                  | `3BF7`             |
| 1: `4000–7FFF` | `7FF7`                     | `77F7`                  | `7BF7`             |
| 2: `8000–BFFF` | `BFF7`                     | `B7F7`                  | `BBF7`             |
| 3: `C000–FFFF` | `FFF7`                     | `F7F7`                  | `FBF7`             |

Ниже показаны именно разряды **адреса порта**. `A15` — старший бит адреса, `A0` — младший. Для
выбора окна используются `A15:A14`; остальные показанные адресные биты выбирают один из трёх
регистров окна.

| Семейство адресов | `A15:A14` — окно  | `A13:A12` | `A11:A10` — регистр | `A9:A8` | `A7:A0` |
| ----------------- | ----------------- | --------- | ------------------- | ------- | ------- |
| `xFF7`            | 00, 01, 10 или 11 | `11`      | `11`                | `11`    | `F7`    |
| `x7F7`            | 00, 01, 10 или 11 | `11`      | `01`                | `11`    | `F7`    |
| `xBF7`            | 00, 01, 10 или 11 | `11`      | `10`                | `11`    | `F7`    |

Например, в `FBF7` `A15:A14=11` выбирает окно 3, а `A11:A10=10` выбирает его регистр защиты.
`A13:A12=11`, `A9:A8=11` и младший байт `F7` фиксированы. Эти адресные биты **не включают защиту**.
Её включает один бит данных: `D0=1` — защита включена, `D0=0` — снята; `D7:D1` игнорируются.

**Адрес выбирает регистр, данные задаются отдельно.** При `OUT (C),A` адрес порта передаётся в `BC`,
а байт настройки — в `A`. Например, `OUT` в `FFF7` с данными `40h` — это запись `40h` в регистр
типа/базового номера окна 3. Само число `FFF7` не является номером RAM.

Доступ к этим портам требует теневого режима. Меняется только активная карта. Чтобы настроить вторую
карту, переключите её битом `7FFD.4`, выполните записи, затем при необходимости вернитесь к прежней
карте. Переключение сразу применяет настройки всех четырёх окон выбранной карты.

**1. Выберите RAM или ROM и способ подстановки номера (`xFF7`).**

При записи в этот порт FPGA разбирает байт данных `D` так:

- D6=1 выбирает RAM; D6=0 выбирает Flash ROM.
- D7=1 разрешает подстановку части номера страницы из `7FFD` (для RAM) или сигнала DOS (для ROM);
  D7=0 использует базовый номер без подстановки.
- D5:D0 задают инверсный шестибитный базовый номер: физическая страница равна `(~D) & 3Fh`. `D`
  здесь — именно байт, записанный в порт, а `~` инвертирует биты этого байта.

Битовая схема байта данных для трёх регистров окна:

| Порт данных | Используемые биты | Значение                                     |
| ----------- | ----------------- | -------------------------------------------- |
| `xFF7`      | `D7`              | 1 — подстановка из `7FFD`/DOS, 0 — выключена |
| `xFF7`      | `D6`              | 1 — RAM, 0 — Flash ROM                       |
| `xFF7`      | `D5:D0`           | Инверсный базовый номер страницы             |
| `x7F7`      | `D7:D0`           | Инверсный полный номер RAM (8 бит)           |
| `xBF7`      | `D0`              | 1 — защита включена, 0 — запись разрешена    |
| `xBF7`      | `D7:D1`           | Игнорируются                                 |

Запись `xFF7` заменяет сохранённый номер страницы целиком: FPGA записывает в старшие два бита номера
нули, а в младшие шесть — инверсию D5:D0. Поэтому при `D7=0` запись в `xFF7` задаёт физическую
RAM-страницу в диапазоне `00h–3Fh`. Байты из `xFF7` задают весь номер страницы внутри этого
диапазона. Например, данные `7Ah` в `FFF7` выбирают RAM и страницу `05h`: `(~7Ah) & 3Fh = 05h`. ROM
использует инверсные константы ERS; примеры есть в исходниках загрузчика.

**2. Для RAM задайте старшие биты номера (`x7F7`), если они нужны.**

Байт данных этого порта — инверсный полный номер RAM: физическая страница равна `~D` (восемь бит).
Запись также выбирает RAM. Для физической страницы 80h это байт `7Fh`, потому что `~7Fh = 80h`.
`x7F7` задаёт все восемь битов страницы, в том числе старшие два, поэтому для страниц выше `3Fh`
нужны две последовательные настройки, но их значения **не складываются**: сначала `xFF7` задаёт тип
RAM и выключает подстановку, затем `x7F7` заменяет номер страницы полным восьмибитным номером.

Повторная запись в `xFF7` тоже заменяет номер целиком, но устанавливает старшие два бита страницы в
`00`. Поэтому после ранее выбранной страницы выше `3Fh` запись только в `xFF7` вернёт отображение в
диапазон `00h–3Fh`. Если подстановка уже выключена и нужно поменять страницу выше `3Fh`, достаточно
новой записи в `x7F7`. Но `x7F7` **не отключает** подстановку D7, ранее заданную через `xFF7`; если
она могла быть включена, сначала запишите `xFF7` с D7=0.

Формулы показывают, как диспетчер вычисляет физический номер RAM, если в `xFF7` включена подстановка
из `7FFD` (D7=1). Бит `EFF7.2` выбирает схему адресации: 1 — 128K, 0 — 1024K. При смене банка в
`7FFD` его биты занимают указанные позиции номера страницы; остальные биты берутся из базового
номера окна:

```text
128K:   page = (base_page & F8h) | (7FFD & 07h)
1024K:  page = (base_page & C0h) | ((7FFD >> 2) & 38h) | (7FFD & 07h)
```

При `EFF7.2=1` включена адресация 128K: из `7FFD` берутся три младших бита номера страницы. При
`EFF7.2=0` включена адресация 1024K: из `7FFD` берутся шесть битов. Этот бит задаёт схему адресации
страниц. Фактический объём RAM определяется установленной памятью. `7FFD` задаёт значения
подставляемых битов. Если подстановка не нужна, задайте D7=0; тогда номер берётся из настроек окна.
Выбор режима и смысл битов `7FFD` описаны в [§3.5](#spectrum-control).

**3. Защитите окно от записи (`xBF7`).**

Запись `01h` запрещает CPU изменять RAM в этом окне; запись `00h` снимает защиту. Проверяется только
D0 записываемого байта. Например, для окна 3 запишите `01h` в `FBF7`, чтобы защитить `C000–FFFF`,
или `00h` в `FBF7`, чтобы разрешить запись. Здесь `FBF7` выбирает регистр защиты окна 3, а `01h` или
`00h` — его новое состояние. Защита действует только в активной карте. Она также блокирует запись в
Flash через это окно, даже если разрешение Flash включено через `BF.1`. После аппаратного сброса
защита снята.

**Пример: показать физическую RAM-страницу 80h по адресу C000.**

Перед примером откройте теневые порты и убедитесь, что диспетчер страниц включён. Из RAM теневые
порты можно открыть, установив `BF.0` с сохранением остальных битов. Код, стек и данные, которые нужны во время
переключения, разместите вне `C000–FFFF`. Если обработчик INT или NMI использует это окно, исключите
его выполнение на время работы с новым отображением. Для временного переключения сохраните
исходную настройку окна и значение BF перед изменением. Восстановите окно до записи сохранённого
BF. [Системный порт ATM](#atm-control) ·
[Чтение конфигурации](#configuration-readback)

Сначала запишите `40h` в `FFF7` (RAM без подстановки), затем `7Fh` в `F7F7` (инверсный номер
страницы 80h). Последние две записи показывают, как включить и снять защиту окна.

```asm
        ld bc,0xFFF7      ; адрес регистра типа/базового номера окна 3
        ld a,0x40         ; данные: RAM, подстановка выключена
        out (c),a
        ld bc,0xF7F7      ; адрес регистра полного номера RAM окна 3
        ld a,0x7F         ; данные: инверсия физической страницы 80h
        out (c),a

        ld bc,0xFBF7      ; адрес регистра защиты окна 3
        ld a,0x01         ; запретить записи CPU в C000–FFFF
        out (c),a
        xor a             ; A=00: разрешить записи снова
        out (c),a
```

Принудительные отображения RAM0 и NMI имеют приоритет над обычным окном и могут обходить его защиту.
Подстановка страницы FE для эмуляции дисковода имеет отдельный временный запрет записи.

<a id="spectrum-control"></a>

### 3.5 `7FFD`, `EFF7` и обычная карта Spectrum

`7FFD` — управляющий порт, в который программа записывает байт настроек памяти и экрана. Один из его
битов выбирает активную карту памяти: бит 4=0 включает карту 0, бит 4=1 — карту 1. Далее этот бит
обозначается `7FFD.4`. Смена карты одновременно применяет заранее сохранённые настройки всех четырёх
окон; заново записывать настройки каждого окна не требуется.

Остальные биты этого порта описаны в таблице ниже. Сам `7FFD` доступен только на запись; последний
сохранённый байт можно прочитать через порт `0ABD`.

| Поле `7FFD` | 128K                                                                               | Pentagon 1024K                 |
| ----------- | ---------------------------------------------------------------------------------- | ------------------------------ |
| 2:0         | Три младших подставляемых бита RAM                                                 | Три младших из шести битов RAM |
| 3           | 0 показывает экран 0, 1 — экран 1; [страницы зависят от видеорежима](#video-modes) | То же                          |
| 4           | Активная карта 0/1                                                                 | Активная карта 0/1             |
| 5           | Блокировка следующих записей `7FFD`, если `EFF7.2=1`                               | Бит 3 номера RAM               |
| 7:6         | Не участвуют в 128K-номере                                                         | Биты 5:4 номера RAM            |

Блокировка зависит от режима 128K/1024K; возврат к 1024K может её снять. Сохранённый байт и значения
для дальнейшей логики различаются: FPGA маскирует расширенные биты в 128K. Для сохранения исходного
регистра читайте `0ABD`.

| Бит  | Назначение                          | Действие                                                                                                                                                                                |
| ---- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0    | Режим 16-цветной графики            | При `xx77.D2:0=3` значение 1 выбирает 256×192 с цветом каждого пикселя; 0 передаёт выбор формата биту 5. [Режимы](#video-modes), [формат байтов](#video-addressing)                     |
| 2    | Схема адресации RAM: 128K или 1024K | 1 — подстановка трёх младших битов номера из `7FFD` и блокировка через `7FFD.5`; 0 — подстановка шести битов, блокировка выключена. Действует для окон с включённой подстановкой номера |
| 3    | Временная подстановка страницы RAM0 | 1 показывает физическую RAM-страницу 0 по `0000–3FFF`; 0 возвращает настройку окна 0. Более приоритетные подстановки перечислены ниже                                                   |
| 4    | Выбор частоты CPU                   | 1=3,5 МГц, 0=7 МГц, если `xx77.D3` не задаёт 14 МГц                                                                                                                                     |
| 5    | ZX-атрибуты 8×1                     | При `xx77.D2:0=3` и бите 0=0 значение 1 даёт отдельный атрибут каждой группе 8×1 пикселей; 0 использует обычные атрибуты 8×8. [Адреса атрибутов](#video-addressing)                     |
| 7    | Доступ к RTC в обычном режиме       | 1 разрешает выбор индекса через `DFF7` и доступ к данным через `BFF7`; 0 запрещает. Теневые `DEF7`/`BEF7` от этого бита не зависят. [Порядок обращения](#rtc-access)                    |
| 1, 6 | Не назначены                        | Функция в исходниках не установлена; сохранять или записывать нули                                                                                                                      |

`EFF7` сбрасывается в ноль и записывается только в обычном режиме. При выключенном диспетчере
приоритет имеет сервисное ПЗУ. При включённом порядок подстановок: NMI (физическая FF), затем
эмулятор FE, затем RAM0.

ERS настраивает привычную карту: RAM5 в `4000`, RAM2 в `8000`, банк `7FFD` в `C000` и BASIC/DOS в
`0000`. Набор ПЗУ использует инверсные константы ROM. Карта Spectrum — **программная настройка
диспетчера ATM**. Аппаратная схема позволяет выбирать другие карты.

### 3.6 Чтение конфигурации

| Порт           | Результат                                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `00BD`–`03BD`  | Инверсные базовые номера карты 0, окна 0–3                                                                                                             |
| `04BD`–`07BD`  | То же для карты 1                                                                                                                                      |
| `08BD`         | Биты `ramnrom`, номер бита `карта*4+окно`; 1=RAM                                                                                                       |
| `09BD`         | Для каждого окна: 1 разрешает подстановку битов номера из `7FFD` или сигнала DOS, 0 использует базовый номер; [правила подстановки](#window-mapping)   |
| `0ABD`         | Исходный сохранённый байт `7FFD`                                                                                                                       |
| `0BBD`         | Исходный сохранённый байт `EFF7`                                                                                                                       |
| `0CBD`         | D7=A14, D6=A9, D5=A8 записи `xx77`; D4=текущий DOS; D3:0=видео/турбо                                                                                   |
| `0DBD`         | Текущий отображаемый цвет в раскладке `xxFF`; см. §5                                                                                                   |
| `0EBD`         | Текущая отображаемая строка глифа; не индексированное чтение шрифта                                                                                    |
| `0FBD`         | Индекс бордюра в D3:0; старшие биты не определены                                                                                                      |
| `10BD`, `11BD` | Младший/старший байт адреса команды, выборка которой вызывает NMI при `BF.4=1`; [ловушка исполнения](#execution-breakpoint)                            |
| `12BD`         | По одному биту на окно: 1 запрещает запись, 0 разрешает. Порядок битов — как в `08BD`; изменять через `xBF7`                                           |
| `13BD`         | D0–D3 разрешают перехват обращений к дисководам A–D соответственно (1=перехватывать); старшие биты не определены. [Условия перехвата](#floppy-overlay) |

Для `08BD`, `09BD` и `12BD` биты 0–3 относятся к окнам 0–3 карты 0, биты 4–7 — к окнам 0–3 карты 1.
Например, бит 6 описывает окно 2 карты 1. В `0CBD` читаются биты адреса из сохранённой настройки
последнего `OUT xx77`. Адрес текущего `IN` в этом регистре не отражается. `0DBD` и `0EBD` зависят от
того, что видеоконтроллер выводит в момент чтения; указать номер цвета или символа этими портами
нельзя.

Порты номеров страниц возвращают инверсию **сохранённого базового номера**. Они не учитывают замену
битов из `7FFD`, сигнал DOS и временную подстановку страницы NMI/эмулятора. Поэтому прочитанное
значение не всегда указывает на физическую страницу, которую CPU видит в данный момент. `12BD` в
этих исходниках **только читается**; защиту меняют записью `xBF7`.

Каждая карта читается своим портом **независимо от того, какая карта сейчас активна**: пока
выполняется код в карте 0, `04BD`–`07BD` всё равно отдают настройки карты 1, переключать карту ради
чтения не нужно. Поскольку возвращается инверсия, `IN` из `0?BD` и маска `3Fh` дают ровно те шесть
битов номера, которые были записаны в `xFF7` (или полный номер после записи в `x7F7`).

Для восстановления обеих карт выберите каждую через `7FFD.4`, восстановите тип и подстановку через
`xFF7`, при необходимости полный RAM-номер через `x7F7`, затем защиту через `xBF7`. В конце
восстановите `EFF7`, `7FFD`, `xx77` и `BF`, обеспечивая нужный теневой режим и доступность
исполняемого кода/стека. Слишком раннее восстановление `7FFD` может выбрать другую карту или
заблокировать дальнейшие записи.

<a id="configuration-readback-port"></a>

**Порт чтения зависит от сборки FPGA.** Здесь описан
[`fpga/base_trdemu`](fpga/base_trdemu/trunk/) — в нём конфигурация читается с `xxBD`
(`ZXEVBD = 8'hBD`, таблица `portbdmux` в [`zports.v`](fpga/base_trdemu/trunk/z80/zports.v)). В
сборках [`fpga/baseconf`](fpga/baseconf/trunk/) и [`fpga/sdload`](fpga/sdload/trunk/) тот же
мультиплексор перенесён на `xxBE` (`ZXEVBE`, `portbemux`), а `xxBD` стал портом адреса ловушки
исполнения (`ZXEVBRK`). Программа, которая должна работать на обеих сборках, читает `xxBD` и, если
значение не совпало с ожидаемым, повторяет чтение с `xxBE`.

### 3.7 Программирование Flash

`BF.1` только разрешает запись, но не выдаёт команды стирания/программирования. Отображённый банк
остаётся Flash со своим протоколом команд, размером стираемых блоков и идентификатором микросхемы. В
`docs/datasheets` есть описания нескольких применявшихся микросхем; алгоритм должен соответствовать
установленной. Обычная `LD (address),A` не превращает Flash в RAM. Пример реализации — прошивальщик
в [`rom/mainmenu/src`](rom/mainmenu/src/).

Исполняйте прошивальщик из RAM, обеспечьте отображение нужных банков так, чтобы код прошивальщика и
его стек оставались доступны CPU, выключите дублирование записей в шрифт, по окончании восстановите
разрешение записи и защиту. Область custom ROM размером 64 КиБ по младшим адресам Flash не является
образом прошивки AVR.

Проверить, доходят ли команды до микросхемы, можно режимом autoselect (`AAh`/`55h`/`90h`), он только
читает. У Am29F040B таблица ответов такая (Table 3 в
[описании](docs/datasheets/am29f040b.pdf)): `A1=0,A0=0` — производитель `01h`, `A1=0,A0=1` — тип
`A4h`, а при `A1=1` читается **бит защиты сектора** (`01h` — защищён, `00h` — нет), причём `A0` уже не
важен. То есть по адресам `XX02` и `XX03` будет одно и то же, и четыре разных байта не обязательны:
проверять «тип повторился» бессмысленно. У совместимых микросхем код типа может отличаться от `A4h`;
сверяйтесь с описанием установленной. Разблокировка `AAh`/`55h` должна идти с задержками,
достаточными для микросхемы, иначе ответа не будет.

Источники: [`atm_pager.v`](fpga/base_trdemu/trunk/mem/atm_pager.v),
[`zdos.v`](fpga/base_trdemu/trunk/z80/zdos.v), [`zmem.v`](fpga/base_trdemu/trunk/z80/zmem.v),
[`zports.v`](fpga/base_trdemu/trunk/z80/zports.v), [`global_vars.a80`](rom/global_vars.a80),
[`services.a80`](rom/page0/source/services.a80).

## 4. Частоты процессора и параметры растра

<a id="cpu-clock"></a>

### 4.1 Выбор частоты и задержки

| `xx77.D3` | `EFF7.D4` | Частота                         |
| --------- | --------- | ------------------------------- |
| 0         | 1         | 3,5 МГц                         |
| 0         | 0         | 7 МГц                           |
| 1         | Любое     | 14 МГц с переменными задержками |

После аппаратного сброса выбраны 7 МГц; ERS может применить сохранённую настройку. FPGA применяет
новую частоту во время refresh-части цикла M1. Поэтому смена происходит не обязательно в момент
записи `OUT`.

На 3,5/7 МГц пропускной способности памяти обычно хватает для реализованных режимов видео. Однако
«без WAIT» не гарантирует постоянное время любого ввода-вывода: данные RTC/UART ожидают AVR. На 14
МГц задержки зависят от арбитража RAM, небольших кешей кода/данных, входа в ROM DOS и обращений
AY/ВГ93. Эффективная скорость зависит от программы; 14 МГц не означают ровно 4× производительности
Spectrum.

<a id="raster-timing"></a>

### 4.2 Видеорежим Z80 и растр платы

Z80-программа может менять **формат изображения** портами `xx77` и `EFF7`: например, выбрать ZX,
ATM-графику или текст. См. [таблицу видеорежимов](#video-modes).

**Код растра Z80 напрямую не задаёт.** Его передаёт AVR в FPGA при настройке видеовыхода. В базовой
прошивке клавиша Scroll Lock циклически меняет сочетание TV/VGA и одного из четырёх растров. Таблица
показывает длительность строки и кадра для каждого растра. Выбранные тайминги влияют также на фазы
бордюра и кадрового прерывания, что важно при разработке Z80-программ с точной синхронизацией.

В столбце «код» указано значение `modes_raster[1:0]` — двухбитного поля, передаваемого AVR в битах
D5:4 внутреннего SPI-регистра конфигурации FPGA. Этот SPI-регистр недоступен программе Z80 как порт
ввода-вывода.

| Код | Растр         | Строк/кадр | Тактов 3,5 МГц/строку | Тактов/кадр |
| --- | ------------- | ---------- | --------------------- | ----------- |
| 0   | Pentagon      | 320        | 224                   | 71680       |
| 1   | Около 60 Гц   | 262        | 224                   | 58688       |
| 2   | Spectrum 48K  | 312        | 224                   | 69888       |
| 3   | Spectrum 128K | 311        | 228                   | 70908       |

Значения следуют из счётчиков исходников. Фазы бордюра и прерывания также зависят от растра; для
точных эффектов учитывайте длину кадра и детали `video_sync_h.v` / `video_sync_v.v`.

Contention в верхнем модуле разрешён и действует на 3,5 МГц при кодах 2/3. Для 48K задерживается
область `4000–7FFF`; для 128K также `C000–FFFF`, если `7FFD` выбирает нечётный банк. FPGA также
добавляет эти задержки к обращениям по чётным I/O-адресам, даже если по конкретному адресу не выбран
встроенный порт. Селектор типа `+2A/+3` подключён к нулю; комментарий TODO не означает готового
режима +3.

VGA удваивает строки этих растров. Это не кадровый буфер PC VGA и не обычный интерфейс 640×480/60
Гц. Растр 60 Гц меняет тайминги, видимые программе.

### 5.2 Формулы адресации

Ниже все смещения **байтовые внутри физической страницы 16 КиБ**. Начало координат в левом верхнем
углу. База окна CPU, куда включена страница, в формулы не входит.

Для адресации байтов пиксельного изображения (bitmap) в режимах Spectrum:

```text
zx(y, xb) = ((y & C0h) << 5) | ((y & 07h) << 8)
          | ((y & 38h) << 2) | xb
```

`xb=0..31` — номер восьмипиксельного байта; `y=0..191`. Формула задаёт тот же чередующийся порядок
строк, что и у Spectrum 48K: начало строки 0 — `0000h`, строки 1 — `0100h`, строки 7 — `0700h`,
строки 8 — `0020h`, строки 16 — `0040h`. Поэтому соседние строки не лежат по соседним адресам
памяти.

**Spectrum:** пиксели находятся в `zx(y,xb)`, атрибут — в `1800h+(y>>3)*32+xb`. Биты 7→0 идут слева
направо. INK=`{attr6,attr2:0}`, PAPER=`{attr6,attr5:3}`, бит 7 включает FLASH.

**ZX hardware multicolor:** адрес bitmap тот же, атрибут соответствующего байта находится в
`2000h+zx(y,xb)`, с тем же INK/PAPER/FLASH.

**Два 16-цветных пикселя в байте (Pentagon/ATM):** формат цветового байта — `IiGRBgrb`. Индекс
левого пикселя `{D6,D2,D1,D0}`, правого `{D7,D5,D4,D3}`. Это не обычные старшая/младшая тетрады
packed RGBI.

В **256×192, 16 цветов** группа из восьми пикселей при `z=zx(y,xb)` читается слева направо:

| Байт | Экран 0               | Экран 1               |
| ---- | --------------------- | --------------------- |
| 0    | Страница 4, `z`       | Страница 6, `z`       |
| 1    | Страница 5, `z`       | Страница 7, `z`       |
| 2    | Страница 4, `2000h+z` | Страница 6, `2000h+z` |
| 3    | Страница 5, `2000h+z` | Страница 7, `2000h+z` |

Каждый байт даёт два последовательных пикселя в указанном цветном формате. Значит, строки 0 и 1 дают
четыре пикселя: по одному байту со страниц 4 и 5 (или 6 и 7) по смещению `z`. Строки 2 и 3 дают ещё
четыре пикселя — по байту с тех же страниц по смещению `2000h+z`. Итого четыре байта × два пикселя =
восемь пикселей в группе.

Для **графики ATM** раскладка строк линейная: `o=y*40+g`, где `y=0..199`, `g=0..39`. Следующая
строка начинается после 40 групп предыдущей. В 320×200 группа содержит восемь пикселей, в 640×200 —
шестнадцать:

| Часть | Экран 0               | Экран 1               |
| ----- | --------------------- | --------------------- |
| 0     | Страница 1, `o`       | Страница 3, `o`       |
| 1     | Страница 5, `o`       | Страница 7, `o`       |
| 2     | Страница 1, `2000h+o` | Страница 3, `2000h+o` |
| 3     | Страница 5, `2000h+o` | Страница 7, `2000h+o` |

В ATM 320×200 части 0, 1, 2 и 3 дают по два пикселя: четыре байта на группу из восьми пикселей. В
640×200 части 1 и 3 содержат байты пикселей левой и правой половин группы, а части 0 и 2 — их
атрибуты. INK ATM=`{D6,D2:0}`, PAPER=`{D7,D5:3}`; бит 7 — отдельная яркость PAPER, **не FLASH**.

Для **текста ATM** `g=x>>1`, `y=0..24`, `o=y*64+g`:

| Поле                     | Двухстраничный режим 6, экран 0 | Одностраничный режим 7, экран 0 |
| ------------------------ | ------------------------------- | ------------------------------- |
| Символ чётной колонки    | Страница 5, `01C0h+o`           | Страница 8, `01C0h+o`           |
| Атрибут чётной колонки   | Страница 1, `21C0h+o`           | Страница 8, `31C0h+o`           |
| Символ нечётной колонки  | Страница 5, `21C0h+o`           | Страница 8, `11C0h+o`           |
| Атрибут нечётной колонки | Страница 1, `01C1h+o`           | Страница 8, `21C1h+o`           |

Для экрана 1 замените страницы на 7/3 в режиме 6 либо 10 в режиме 7. `+1` для нечётного атрибута
указан намеренно. Это не линейные строки по 80 байтов и не чередование символ/атрибут. Атрибуты
имеют формат ATM. Код символа индексирует загруженный шрифт 8×8. Соответствие кодов KOI8/CP866
задаётся изображениями символов в шрифте; отдельного аппаратного декодера кодировки нет.

<a id="border"></a>

### 5.3 Бордюр

Запись `xxFE` выбирает `D2:0` (0–7), `xxF6` — `8|D2:0` (8–15). `xxFC` — алиас `xxFE` для цветов
0–7: он меняет бордюр, не трогая выходы бипера и ленты. Но при `A15=0` адрес `xxFC` одновременно
декодируется как запись в `7FFD` и может изменить страницу RAM и выбор экранной страницы (если
`7FFD` не заблокирован). Для записи только цвета бордюра используйте `80FC` или другой адрес `xxFC`
с `A15=1`. Изменение бордюра может синхронизироваться с растром, поэтому видимая фаза `OUT` зависит
от растра/турбо. Бордюр тоже использует программируемую палитру. Его сохранённый индекс читается
через `0FBD`.

<a id="atm-palette"></a>

### 5.4 Палитра ATM: 16 цветов из 64

Палитра ATM применяется **во всех видеорежимах**: после формирования пикселя FPGA берёт его 4-битный
индекс и преобразует его в RGB через одну из 16 записей палитры. Это относится и к цветам бордюра.
Поэтому запись элемента ATM-палитры меняет соответствующий индекс в ZX, Pentagon, ATM-графике и
текстовых режимах. `BF.5` меняет точность компонентов этой же палитры, но не выбирает отдельный
видеорежим. Отдельный путь ULAplus использует свою палитру из 64 цветов при включённом ULAplus в
поддерживаемом растре; см. ниже.

`xxFF` — адрес порта: `FF` — младший байт, `xx` — старший байт адреса. При обычной палитре
(`BF.5=0`) значение `xx` не выбирает цветовой индекс. В FPGA адрес записи берётся из текущего сигнала
`zxcolor`: в активной области растра это 4-битный индекс выводимого пикселя, вне её — индекс бордюра.
Если включена синхронизация бордюра, вне активной области используется защёлкнутое значение бордюра.
Именно этот индекс выбирает запись палитры при стробе `atm_palwr`; отдельного регистра выбора элемента
нет. Запись при выводе пикселя с индексом 2 изменит элемент 2, а запись на бордюре с индексом 2 — тот
же элемент. В активной области индекс может меняться на каждом пикселе; для управляемой записи обычно
используют длинный верхний бордюр во время кадрового гашения. При включённой синхронизации значение
бордюра защёлкивается сигналом `border_sync` каждые **8 тактов растра**, а не раз за строку:
в `video_sync_h.v` проверяются только младшие три бита `hcount`. После смены индекса нужно дать
защёлке обновиться перед записью `xxFF`; ждать целую строку не требуется. Если синхронизация
бордюра выключена, используется его текущий индекс напрямую (`video_palframe.v`). Для установки
всей палитры можно один раз дождаться начала длинного бордюрного интервала и последовательно
менять индекс бордюра и записывать цвет, оставаясь вне активной области.

Запись разрешается адресом `xx77` с A14=0. После записи `xxFF` запретите запись палитры. При этом
`xxFF` продолжает менять системный регистр дисковода. При расширенном RGB444 (`BF.5=1`) часть битов
`xx` задаёт младшие биты компонентов цвета, как описано в §5.5; правило выбора индекса палитры при
стробе записи остаётся тем же.

Каждый цветовой канал задаётся двумя битами: заглавная буква — старший бит, строчная — младший.
Например, `Rr=10` — красный канал со значением 2 из 3, `Gg=01` — зелёный со значением 1, `Bb=11` —
синий со значением 3. В записи `grbG00RB` сначала идут младшие биты зелёного, красного и синего,
затем старший бит зелёного, два служебных разряда и старшие биты красного и синего.

| Бит данных `xxFF` | Значение                                                 |
| ----------------- | -------------------------------------------------------- |
| 7                 | `~g`                                                     |
| 6                 | `~r`                                                     |
| 5                 | `~b`                                                     |
| 4                 | `~G`                                                     |
| 3, 2              | Держать в 1 для нормальной работы контроллера дисководов |
| 1                 | `~R`                                                     |
| 0                 | `~B`                                                     |

Байт, который программа записывает в `xxFF`, — побитовая инверсия шаблона `grbG00RB`. Например, для
`Rr=10`, `Gg=01`, `Bb=11` шаблон равен `A3h`, поэтому в порт записывают `5Ch`; его биты 3:2 равны 1.
В таком формате процедуры ERS передают цвета палитры. Это не порядок битов RGB222. Начальную палитру
задаёт ПЗУ; RAM FPGA не гарантированно обнулена.

`0DBD` читает цвет, выбранный сигналом `zxcolor`. Для обычной палитры, если `W` — байт записи `xxFF`,
а `R` — результат чтения `0DBD`, аппаратная перестановка при записи и чтении взаимно компенсируется:
цветовые биты совпадают (`R7:4=W7:4`, `R1:0=W1:0`), а D3:2 читаются единицами. Поэтому считанный
байт можно использовать для восстановления записи палитры. В FPGA чтение зарегистрировано, поэтому
цвет относится к сигналу выбора предыдущего такта пиксельного тактового сигнала. Это не независимое
чтение по заданному номеру элемента и не значение, выбранное последним `OUT xxFF`. Чтобы прочитать
всю палитру, нужно последовательно вывести нужные индексы (например, бордюром) и учитывать задержку
относительно растра.

<a id="rgb444"></a>

### 5.5 RGB444 и ограничения ULAplus

`BF.5` включает расширенный ввод палитры ATM. Байт, записываемый в `xxFF`, задаёт старшие два бита
каждой четырёхбитной компоненты; биты старшего байта адреса порта задают младшие два бита:

| Компонента    | Данные       | Адрес          |
| ------------- | ------------ | -------------- |
| R3,R2 / R1,R0 | `~D1`, `~D6` | `~A9`, `~A14`  |
| G3,G2 / G1,G0 | `~D4`, `~D7` | `~A12`, `~A15` |
| B3,B2 / B1,B0 | `~D0`, `~D5` | `~A8`, `~A13`  |

Используйте `OUT (C),A` для независимого задания адреса и данных. Видеоконтроллер хранит 12-битный
цвет (по 4 бита на канал), но физический видеовыход передаёт по 2 бита на канал. Внутренний модуль
FPGA [`video_palframe_mk3bit`](fpga/base_trdemu/trunk/video/video_palframe.v) преобразует 4-битный
уровень каждого канала в 2-битный и чередует уровни соседних градаций по пикселям, строкам и кадрам.
Так аппаратно имитируются промежуточные оттенки. Регистр 12 бит не означает ЦАП 12 бит или
одинаковый аналоговый цвет на любой плате. `0DBD` выдаёт только шестибитную часть: этого
**недостаточно для сохранения полной RGB444-палитры**, нужна программная копия.

ULAplus имеет отдельные 64 элемента. Запишите индекс `0..63` в `BF3B`, затем цвет `GGGRRRBB` в
`FF3B`. Для включения/выключения запишите `40h` в `BF3B`, затем D0=1/0 в `FF3B`. Чтение `xx3B`
возвращает последний записанный байт в FF3B. Это чтение не позволяет узнать содержимое выбранного
элемента палитры или отдельно запросить текущее разрешение ULAplus.

В атрибуте ULAplus `attr7:6` выбирают подпалитру 0–3: INK=`(attr>>6)*16+(attr&7)`,
PAPER=`(attr>>6)*16+8+((attr>>3)&7)`. FLASH/BRIGHT становятся битами подпалитры; бордюр использует
первые восемь элементов.

**Ограничение базовой реализации:** `video_palframe.v` выбирает ULAplus только при `up_ena=1` **и
коде растра 3 (128K)**. Руководство описывает применение к ZX/ZX-multicolor более общо. Для этих
исходников одного разрешения ULAplus при обычном растре Pentagon недостаточно. Расширение цветов
ULAplus в общую 12-битную палитру также проходит через стадию дизеринга.

### 5.6 ОЗУ шрифта

Текстовый режим ATM (режим 6) и текстовый режим Evolution (режим 7) используют одно и то же ОЗУ
шрифта объёмом 2 КиБ. Отдельного шрифта для каждого режима или текстовой страницы нет: при
переключении режима или страницы рисунок символов не меняется. Загрузка нового шрифта меняет символы
сразу в обоих текстовых режимах.

ОЗУ шрифта хранит изображения 256 символов (глифы) по восемь байтов. Строка `r` символа `n`
находится по `n*8+r`; биты 7→0 идут слева направо. `BF.2` дублирует **каждую запись CPU в память** в
адрес шрифта `CPU_address & 07FFh`. Обычная память одновременно тоже записывается. Поэтому
сохранение адреса возврата на стек при прерывании и любые посторонние записи в память могут
испортить шрифт, пока разрешение включено.

Для загрузки несжатого шрифта из 2048 байтов запретите прерывания и включите `BF.2`. Источник и
приёмник должны оставаться видимыми CPU на протяжении копирования. Приёмником выберите свободную
область RAM, которую можно перезаписать; её адрес должен иметь нужные младшие 11 битов. Например,
копирование в `8000–87FF` одновременно заполнит адреса `000–7FF` ОЗУ шрифта. После копирования
сбросьте `BF.2` и только затем восстановите прерывания. Сохраняйте остальные биты BF. Этот способ
принимает несжатые изображения символов, тогда как функция ERS `57h` в этих исходниках ожидает
сжатый шрифт.

`0EBD` выдаёт текущий отображаемый байт строки символа. Индексированного чтения RAM шрифта со
стороны CPU нет. Пример синхронного считывания изображения —
[`docs/fontread.src`](docs/fontread.src); задержки зависят от частоты/растра.

Источники: [`video_modedecode.v`](fpga/base_trdemu/trunk/video/video_modedecode.v),
[`video_addrgen.v`](fpga/base_trdemu/trunk/video/video_addrgen.v),
[`video_render.v`](fpga/base_trdemu/trunk/video/video_render.v),
[`video_palframe.v`](fpga/base_trdemu/trunk/video/video_palframe.v),
[`video_fontrom.v`](fpga/base_trdemu/trunk/video/video_fontrom.v),
[`zports.v`](fpga/base_trdemu/trunk/z80/zports.v).

## 6. Прерывания и NMI

### 6.1 Кадровое прерывание базовой реализации

За один видеокадр видеоконтроллер запрашивает у Z80 маскируемое прерывание INT. Сигнал INT остаётся
активным до подтверждения со стороны CPU или до окончания счёта 256 тактов генератора 28 МГц. Во
время WAIT счётчик приостанавливается. Если WAIT не активен, импульс длится около 9,14 мкс — это 32
такта Z80 при частоте 3,5 МГц. При turbo-частоте число тактов Z80 за время импульса зависит от
выбранной частоты CPU. При подтверждении прерывания Z80 читает `FFh`; это подходит для обычной
таблицы IM 2 и обработчика `RST 38h` в IM 0.

Запрос INT не ставится в очередь. Если прерывания CPU запрещены на всё время импульса, программа
пропустит прерывание этого кадра. В базовой реализации нет программируемого растрового прерывания и
прерывания UART на Z80. В §15 описана другая, более новая схема: она сохраняет запрос до обработки.

<a id="nmi-entry"></a>

### 6.2 Вход в NMI

NMI запрашивается клавишей Print Screen, физическим входом NMI через AVR, переходом `BF.3` из 1 в 0
или совпадением адреса команды с заданным в `10BD` / `11BD`. Запросы от Print Screen, внешнего входа
и `BF.3` выполняются в начале следующего кадра. Совпадение адреса вызывает NMI сразу после выборки
опкода.

При входе в NMI CPU сохраняет адрес возврата на исходном стеке и устанавливает PC в `0066h` —
шестнадцатеричный адрес в пространстве адресов Z80. FPGA один раз выдаёт по этому адресу команду
`NOP`. После её выборки FPGA отображает RAM-страницу **FF** в окно 0 (`0000–3FFF`). В ERS она
обозначена как `RAM_NMI=00h` — инверсный номер страницы. Следующая команда читается по CPU-адресу
`0067h`, из смещения `0067h` страницы FF. Поместите первый байт NMI-обработчика по этому адресу.

Собственный обработчик должен сразу сохранить SP, перейти на свой стек, сохранить регистры и
состояние разрешения прерываний IFF2, затем прочитать регистры конфигурации `xxBD`, прежде чем
менять настройки. `LD A,I` / `LD A,R` показывают IFF2 во флаге P/V. Первичные записи стека
происходят до подстановки страницы: исходный стек должен допускать запись. Аппаратная подстановка
NOP может нарушить команду, если одна из её выборок опкода приходится на 0066, например у команды с
префиксом. Кроме того, первичные записи адреса возврата могут повредить код или данные, если стек
расположен неудачно. Поэтому этот механизм требует проверки размещения кода и стека при разработке
собственного обработчика.

ERS уже занимает физическую FF кодом и рабочей областью NMI/RST. Замена обработчика заменяет часть
среды исполнения ERS.

### 6.3 Выход из NMI

Восстановите регистры, исходный стек и требуемое IFF2. Завершение:

```asm
        out (0xBE),a       ; значение данных игнорируется
        retn               ; непосредственно следующая команда
```

При NMI порт BE запускает отложенное отключение подстановки через следующие два события M1/refresh:
оба байта `RETN` успевают исполниться до возврата карты. Аппаратура не распознаёт саму инструкцию
RETN: вставлять другие команды небезопасно. RETN переносит IFF2 в IFF1; `DI`/`EI` внутри обработчика
меняют также IFF2. Если обработчик использовал DI/EI, перед выходом восстановите то состояние
разрешения прерываний, которое требуется прерванной программе.

NMI, синхронизированное с кадровым INT, может заменить ожидаемый обработчик кадра. Монитор,
возвращающийся в программу, зависящую от точного времени исполнения, должен это учитывать.

<a id="execution-breakpoint"></a>

### 6.4 Запрос NMI по адресу команды (breakpoint, точка останова)

Запишите адрес CPU: младший байт в `10BD`, старший — в `11BD`; затем установите `BF.4`. Когда Z80
выбирает опкод по этому адресу (цикл M1), FPGA запрашивает NMI. Проверяется адрес CPU, поэтому после
переключения банка по тому же адресу может находиться другой код. Чтение и запись данных NMI не
вызывают. Опкод, совпавший с заданным адресом, успевает исполниться до перехода в обработчик.
Разрешение сохраняется после срабатывания: обработчику нужно выключить его или задать новый адрес.
Для многобайтных команд учитывайте выборки префиксов.

Источники: [`zint.v`](fpga/base_trdemu/trunk/z80/zint.v),
[`znmi.v`](fpga/base_trdemu/trunk/z80/znmi.v), [`zbreak.v`](fpga/base_trdemu/trunk/z80/zbreak.v),
[`nmi_service.a80`](rom/page5/source/nmi_service.a80).

## 7. Клавиатура, джойстик, мышь и магнитофонный вход

<a id="keyboard"></a>

### 7.1 Матрица Spectrum и сканкоды PS/2

Чтение `xxFE` / `xxF6`: D7=1, D6=tape in, D5=0, D4:0=активные нулём клавиши. Нулевые разряды A15:A8
выбирают полуряды, результаты объединяются AND как на Spectrum. FPGA читает уже сохранённое
состояние, не ожидая AVR при каждом опросе матрицы.

AVR объединяет механическую клавиатуру с переводом PS/2. Одна клавиша PS/2 может соответствовать
двум клавишам Spectrum, включая shift-комбинацию. Актуальная стандартная/EEPROM-раскладка
реализована в `kbmap.c` / `kbmap.h`; старые схемы `docs/kbd-map*.txt` могут отличаться от нынешней
стандартной раскладки. Например, нынешний код отображает левый Shift в CAPS SHIFT, левый Ctrl в
SYMBOL SHIFT, левый Alt в CAPS SHIFT+SYMBOL SHIFT. Физические модификаторы PS/2 нельзя надёжно
определять по эмулируемой матрице.

Для сырых сканкодов выключите окно EEPROM, выберите тип расширения 2 записью в любую ячейку RTC
`F0–FF`, затем читайте эти ячейки. Чтение удаляет один байт; `00` означает пустой буфер, `FF` —
переполнение. Запись бита 0 в RTC `0C` очищает буфер. Поток содержит сканкоды PS/2 и служебные
префиксы. AVR записывает в журнал короткие последовательности нажатия/отпускания (make/break) и не
гарантирует сохранения произвольных длинных ответов клавиатуры. Независимое состояние модификаторов
есть в RTC `0D` (§11).

Если назначить Ctrl или Alt клавишам Spectrum через EEPROM-раскладку, AVR учитывает такое назначение
при обработке служебных сочетаний. Назначенные клавиши Ctrl/Alt исключаются из некоторых сочетаний
управления компьютером, чтобы их использование программой не вызывало служебное действие.

### 7.2 Управляющие клавиши и сброс

| Управление                             | Поведение базовых исходников                                       |
| -------------------------------------- | ------------------------------------------------------------------ |
| Короткий F12                           | Мягкий сброс Z80/регистров FPGA без перезагрузки конфигурации FPGA |
| F12 около 5 секунд                     | Полный сброс прошивки, без запроса выключения ATX                  |
| Ctrl+Alt+Delete                        | Полный сброс с учётом правил отображённых управляющих клавиш       |
| Print Screen / контакт NMI             | Запрос NMI, обычно синхронно началу кадра                          |
| Num Lock                               | Переключение beeper/Covox и tape out; LED означает tape out        |
| Scroll Lock                            | Перебор состояний видеовыхода/растра; см. ниже                     |
| Обе кнопки мыши + keypad `*`, `+`, `-` | Сброс/увеличение/уменьшение разрешения мыши, если поддерживается   |

**Особенность текущего Scroll Lock:** `zx.c` увеличивает комбинированное поле `MODE_VIDEO_MASK=31h`,
перебирая TV/VGA для каждого из четырёх кодов растра. Старая отдельная обработка Shift+Scroll Lock
закомментирована. Описание PDF «TV/VGA и отдельно 60 Гц через Shift» не соответствует этим
исходникам AVR.

Физическая кнопка soft reset/ATX включает питание из выключенного состояния, коротким нажатием
сбрасывает работающую машину, удержанием около пяти секунд запрашивает выключение. Hard reset
перезапускает AVR и загружает FPGA заново. Сохранность RAM обещается только при soft reset; полный
сброс и выключение не являются средствами сохранения данных.

<a id="joystick"></a>

### 7.3 Kempston-джойстик

В обычном режиме `xx1F` возвращает активные единицей D0=вправо, D1=влево, D2=вниз, D3=вверх,
D4=огонь; старшие биты обычно нули. В теневом режиме адрес означает команду/статус ВГ93. Для опроса
джойстика закройте теневые порты.

<a id="mouse"></a>

### 7.4 Kempston-мышь

| Порт   | Результат                                                                  |
| ------ | -------------------------------------------------------------------------- |
| `FADF` | D7:4=4-битный счётчик колеса, D3=1, D2=средняя, D1=правая, D0=левая кнопка |
| `FBDF` | Циклический восьмибитный счётчик X                                         |
| `FFDF` | Циклический восьмибитный счётчик Y                                         |

Значение 0 в бите кнопки означает, что она нажата. Счётчики координат изменяются при движении и
после FFh переходят в 00h. Для получения смещения вычитайте предыдущее значение из нового в
восьмибитной арифметике и трактуйте результат как знаковый: например, переход FFh → 00h даёт +1. Это
не готовая координата указателя на экране. Счётчик колеса аналогично переходит из F в 0; для него
используйте четырёхбитную разность. Без обнаруженной мыши AVR выдаёт FF во всех трёх регистрах; у
мыши без колеса его поле может содержать F. Настройки разрешения 0–3 соответствуют 1/2/4/8 отсчётам
на миллиметр для поддерживающих устройств. Это настройка разрешения PS/2. Экранные координаты
программа задаёт отдельно.

### 7.5 Магнитофонный вход

AVR считывает уровень магнитофонного входа и передаёт его FPGA; CPU читает сохранённый уровень через
`FE.6`. Загрузка TAP — другой механизм: сервис ПЗУ ERS с RAM-буферами и перехватом BASIC. Это не
аппаратный генератор кассетного сигнала; наличие FE.6 не включает TAP-эмуляцию.

## 8. Звук и принтер

<a id="ay-sound"></a>

### 8.1 AY/YM

Номер регистра записывается в `FFFD`, данные — в `BFFD`, чтение выбранного регистра — через `FFFD`.
Звук формирует физическая микросхема AY/YM. К beeper 48K добавляются три тональных канала, шум,
огибающая, регистры ввода-вывода. На 14 МГц обращения AY/ВГ93 получают дополнительные задержки.
Точные частоты/соединения зависят от платы; смотрите её схему и описание микросхемы AY/YM в
`docs/datasheets`.

В ПЗУ есть обработка дополнительных вариантов AY, но это не подтверждает два встроенных чипа или
TurboSound на любой плате. NMI заглушает AY; текущий вызов восстановления AY при выходе
закомментирован. Приложение не должно полагаться на полное сохранение звукового состояния после NMI.

<a id="beeper-covox"></a>

### 8.2 Beeper, tape out и Covox

`FE.4` — beeper, `FE.3` — tape out. AVR `MODE_TAPEOUT` выбирает один сигнал для общего выхода.
Нынешняя FPGA **не складывает их XOR**, вопреки старому английскому руководству.

Запись беззнакового отсчёта `0..255` в `xxFB` включает ШИМ Covox. При 28 МГц несущая около 218,75
кГц. Нет FIFO отсчётов, прерывания частоты дискретизации, DMA и автоматического проигрывания:
моменты записи задаёт программа.

Возврат из Covox к beeper в исходнике зависит от изменения сохранённого состояния
(`beep_bit != beep_bit_old`) при записи FE. Это не старое правило «любая запись FE отключает Covox».
F6 не формирует строб beeper. Учитывайте это, совмещая цифровой звук с эффектами бордюра.

### 8.3 Принтер через AY

Опциональное подключение описано в
[`docs/revb/zxevo_ay_printer.pdf`](docs/revb/zxevo_ay_printer.pdf) и
[`docs/ayprn.txt`](docs/ayprn.txt). ERS предоставляет RST-функции `40–43` для инициализации,
символа, токена BASIC и экрана. Нужны соответствующий драйвер/настройка и подключённое устройство.
Это не штатный Centronics ATM. Ограничения вызовов вне BASIC приведены в разделе API.

[Сервисы накопителей ERS](#rst-storage) · [storage.h](lib/baseconf/include/baseconf/storage.h)

<a id="sd-interface"></a>

### 9.1 SD SPI, интерфейс Z-controller

В обычном режиме запишите `01h` в `0077h`, чтобы выбрать карту, и `03h`, чтобы снять выбор.
Оба значения сохраняют D0=1 для совместимости с Z-controller, а D1 задаёт сигнал CS_n
с активным нулём. В теневом режиме те же значения записываются в `8057h`. При обычной
дешифрации чтение `xx77` всегда возвращает ноль. Контакт наличия карты читайте в
`RTC[0Ch].3`, а контакт разрешения записи — в `RTC[0Ch].2`. Ответ самой карты проверяется
SPI-командами при инициализации. [Управление RTC](#rtc-controls)

Каждое обращение к `xx57` запускает один обмен SPI: одновременно передаются и принимаются восемь
битов. При записи передаётся записанный байт, при чтении — FFh. Результат чтения относится к
**предыдущему завершённому обмену**.

Например, `OUT` с байтом 55h запускает его передачу. Следующий `IN` возвращает байт, принятый
**во время передачи** 55h, и начинает отправку FFh. Ещё один `IN` возвращает байт, принятый
во время передачи этого FFh. Полученный одновременно с передачей байт может содержать
заполнитель. После чтения токена начала данных следующий обмен уже запущен, и следующее чтение
выдаст первый байт блока.

В теневом режиме:

| Доступ                   | Действие                                      |
| ------------------------ | --------------------------------------------- |
| Запись `xx57`, A15=0     | Передача байта                                |
| Запись `xx57`, A15=1     | Управление CS_n через D1, как обычный `xx77`  |
| Чтение `xx57`, любое A15 | Выдать предыдущий байт, запустить передачу FF |

Когда драйвер дождался маркера начала блока и учёл задержку результата на один обмен, сектор можно
прочитать двумя `INIR` при C=57h, B=0. В теневом режиме чтение такое же. Но **теневая запись полного
блока через OTIR на 256 байтов недопустима**: старший адрес меняется, и часть записей с A15=1
изменит CS. Используйте четыре прохода по 128 байтов, каждый раз загружая B=80h: перед `OUT` Z80
уменьшает B, и A15 остаётся нулём. Эта последовательность описывает только передачу блока.
Инициализацию SD, ожидание маркера начала данных (токена), CRC и окончания занятости карты драйвер
обрабатывает отдельно.

Модуль FPGA `spihub` использует фиксированную скорость SPI: `28 МГц / 2 = 14 МГц`. В этом интерфейсе
Z80 не управляет делителем SPI. Порядок инициализации описан в драйвере SD из репозитория.

Общий SD-интерфейс используется и Z80, и AVR. AVR может запросить исключительный доступ, установив
lock; FPGA выдаст его, когда Z80 снимет выбор карты (CS_n=1). Поэтому Z80 должен снимать выбор карты
между транзакциями. Если постоянно держать CS_n=0, AVR не сможет получить доступ.

Арбитраж только исключает одновременную передачу по SPI. Он не согласует кеши и изменения файловой
системы двух независимых программ.

<a id="ide-interface"></a>

### 9.2 IDE и порядок байтов

Nemo IDE доступен и в обычном, и в теневом режиме. Помимо передачи слова через два порта, он
поддерживает последовательную передачу байтов через один порт. LBA означает линейный номер сектора;
CHS — адрес из номера цилиндра, головки и сектора. Master/slave выбирают одно из двух устройств на
общем кабеле IDE.

| Порт   | Чтение                                                               | Запись                                                          |
| ------ | -------------------------------------------------------------------- | --------------------------------------------------------------- |
| `xx10` | Младший байт либо чередование младший/старший                        | Младший после 11 либо последовательные младший/старший          |
| `xx11` | Сохранённый старший байт последнего слова                            | Сохранить старший байт без цикла устройства                     |
| `xx30` | Error: причина ошибки последней команды                              | Features: параметр для команд настройки ATA                     |
| `xx50` | Счётчик секторов                                                     | Счётчик секторов                                                |
| `xx70` | Номер сектора / LBA7:0                                               | То же                                                           |
| `xx90` | Младшая часть цилиндра / LBA15:8                                     | То же                                                           |
| `xxB0` | Старшая часть цилиндра / LBA23:16                                    | То же                                                           |
| `xxD0` | Device/head                                                          | Устройство/головка, LBA/CHS, master/slave                       |
| `xxF0` | Status: занятость, готовность данных и ошибка устройства             | Command: код команды ATA, запускающий операцию                  |
| `xxC8` | Alternate status: состояние без подтверждения запроса прерывания ATA | Device control: программный сброс и управление прерываниями ATA |

`10,30,...,F0` используют ATA CS0 и адрес A7:A5; C8 использует CS1, регистр 6. Декодер принимает
также `08,28,48,68,88,A8,E8` через CS0 с соответствующим A7:A5; C8 — особое исключение CS1. Это
побочные адреса реализации, не ещё один контроллер.

При чтении 16-битного слова в режиме Nemo сначала прочитайте порт `xx10`, затем `xx11`. Первое
чтение получает слово от IDE-устройства: младший байт возвращается CPU, старший сохраняется в FPGA.
Второе чтение выдаёт этот сохранённый старший байт без нового обращения к устройству.

При записи порядок обратный: сначала запишите старший байт в `xx11`, затем младший в `xx10`. Запись
в `xx11` только сохраняет байт в FPGA. Запись в `xx10` передаёт устройству целое слово из обоих
байтов.

Последовательное расширение: повторные обращения к 10 передают младший, затем старший без
перестановки. Сектор 512 байтов можно передать двумя INIR или двумя OTIR по 256 байтов. Перед
началом передачи обратитесь к другому регистру IDE, например command/status: это сбрасывает
чередование, чтобы первый доступ к xx10 снова передавал младший байт. Пока передаётся слово, другой
обработчик или драйвер не должен обращаться к IDE и менять это состояние.

Для опроса можно читать альтернативный статус `xxC8`, сохраняя запрос прерывания ATA.
Пока `BSY` (D7) установлен, дождитесь его сброса. Затем проверяйте `ERR` (D0) и `DF` (D5)
и начинайте передачу только при `DRQ` (D3). Ограничивайте каждый этап ожидания таймаутом.
Текущий `DEVFIND` проверяет встроенный Nemo master. В ERS также есть драйвер ATAPI/CD и
необязательные внешние драйверы. Устройство slave можно выбирать через ATA Device/Head.

Источники: [`zports.v`](fpga/base_trdemu/trunk/z80/zports.v),
[`spihub.v`](fpga/base_trdemu/trunk/spihub/spihub.v),
[`z_sd_drv.a80`](rom/page5/source/fat/z_sd_drv.a80),
[`nemo_drv.a80`](rom/page5/source/fat/nemo_drv.a80),

### 10.1 Физический Beta Disk/ВГ93

| Порт   | Назначение                                                       |

| `xx7F` | Данные                                                           |
| `xxFF` | Системный регистр (W), состояние (R), палитра при разрешении (W) |

Запись FF: D1:0=дисковод 0–3, D2=reset (0 удерживает сброс), D3=HRDY, D4=сторона дискеты. HRDY —
линия контроллера, связанная с готовностью головки: D3 передаётся на неё без инверсии. INTRQ
означает запрос прерывания от контроллера, DRQ — запрос передачи очередного байта. Чтение в этом
исходнике: D7=INTRQ, D6=DRQ, D5=1, D4=**инверсия** внутренней стороны, D3=HRDY, D2=состояние reset,
D1:0=дисковод. Старое утверждение английского PDF о шести младших единицах устарело.

Значения команды/статуса ВГ93 зависят от класса команды. Полноценный драйвер обрабатывает DRQ,
завершение, ошибки, физические интервалы носителя; это не секторный BIOS. Запись палитры FF меняет
тот же регистр выбора диска/reset/ HRDY/стороны и должна учитывать их требуемое состояние.

<a id="floppy-overlay"></a>

### 10.2 Аппаратный перехват FE

Биты `13BD.D3:0` включают перехват для дисководов A–D: бит 0 соответствует A, бит 3 — D; 1 разрешает
перехват. После сброса все биты равны нулю.

При обращении к порту дисковода FPGA проверяет четыре условия: включён DOS, в текущем окне CPU
выбрано ROM, бит выбранного дисковода в 13BD равен 1, запись палитры выключена. Если все условия
выполнены, FPGA заменяет ROM в окне 0 физической RAM-страницей **FE**. Следующая команда читается
уже из RAM по тому же адресу CPU, по которому она была бы прочитана из ROM.

Это механизм подстановки ROM→RAM. Он не запускает NMI и не кладёт отдельный адрес возврата на стек.
Эмулятор должен содержать продолжения на адресах перехватываемых инструкций TR-DOS. Одного BF.0
недостаточно: проверяются DOS, ROM, маска диска и режим палитры.

При включённом перехвате обращения к регистрам ВГ93 не передаются физической микросхеме контроллера.
Однако запись системного порта FF выполняется и по-прежнему меняет выбор дисковода и остальные
управляющие биты. До первого следующего M1 кратковременно запрещена запись, чтобы INI/INIR не
испортили подставленную FE. Программная часть обязана воспроизвести семантику исходного ввода-вывода
и контроллера.

При выходе только из эмуляции `OUT (BE),A` возвращает ROM **со следующей инструкции**: нельзя
автоматически применять отложенную схему RETN для NMI. Если внутри эмуляции пришло NMI, FF получает
приоритет; первый выход BE снимает NMI, последующий выход эмулятора — FE.

### 10.3 Виртуальные накопители ERS и FAT

FE ROM распаковывает эмулятор в физическую FE из образа `dos_fe`. Обычная не-FE сборка устроена
иначе. Прежде чем включать маски дисководов, согласуйте ПЗУ и FPGA. Для этого `RST 08h,4Dh`
выполняет ограниченную проверку: временно записывает тестовую маску в 13BD, читает результат и
восстанавливает прежнее значение.

ERS читает FAT12/16/32, выбирает устройство/раздел, монтирует TRD-файлы, загружает TRD/SCL/FDI в
рамдиск и TAP в буфер ленты. Примонтированный TRD читается/записывается через блочный драйвер; это
не общий FAT API создания, удаления, изменения размера и записи файлов.

Ограничения и владение памятью:

- Сектор FAT — 512 байтов. MBR-сканер обрабатывает четыре первичных записи поддерживаемых типов; он
  не разбирает GPT и не обходит цепочки расширенных разделов.
- Таблицы поиска и вложенности ограничены: до 2048 найденных записей и 16 сохранённых уровней
  каталогов в структурах ПЗУ.
- Для A–D есть четыре описателя по 64 байта, всего 256. Для больших файлов кеш сохраняет адреса
  кластеров с определённым интервалом.
- Автомонтирование описывает `IMAGE.MNT`, разбор ограничен сектором 512 байтов. Формат смотрите в
  mounter/ERS; `IMAGE.FNT` в старых комментариях — опечатка.
- Примонтированный образ имеет приоритет над рамдиском на той же букве.
- Рамдиск содержит около 800 КиБ данных и отдельную таблицу треков/секторов; её маркеры и страницы
  должны сохраняться до отключения.
- Hot-swap SD не является безопасной операцией над открытым файлом. После смены носителя
  переинициализируйте состояние; руководство ERS рекомендует сброс.

Номера функций и форматы описателей приведены в [RST API накопителей](#rst-storage).

## 11. RTC, NVRAM, версии прошивок и EEPROM

<a id="rtc-access"></a>

### 11.1 Доступ и формат

Программа Z80 обращается к регистрам, совместимым с Gluk/DS12877. AVR обслуживает эти обращения,
используя часы PCF8583 и свои переменные. В обычном режиме включите EFF7.7, запишите индекс в DFF7,
читайте/пишите BFF7. В теневом используйте DEF7/BEF7 без зависимости от EFF7.7. Каждое обращение к
**данным** ожидает AVR; запись может быть значительно медленнее чтения кешированного времени. Между
выбором индекса и обращением к данным другой обработчик не должен переключать индекс RTC: иначе вы
прочитаете или запишете другую ячейку.

| Индекс                 | Значение                                                                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `00`, `02`, `04`       | Секунды, минуты, часы                                                                                                                                          |
| `01`, `03`, `05`       | Позиции будильника; прерывания будильника не эмулируются                                                                                                       |
| `06`, `07`, `08`, `09` | День недели 1–7, число, месяц, двузначный год                                                                                                                  |
| `0A`                   | При чтении возвращает 0; запись выбирает 16-байтную страницу EEPROM AVR                                                                                        |
| `0B`                   | Начальное 02; бит2: 1=двоичное время, 0=BCD                                                                                                                    |
| `0C`                   | Флаг обновления времени, клавиатурные LED, наличие SD, выбор окна EEPROM; чтение сбрасывает флаг обновления. [Значения битов и действие записи](#rtc-controls) |
| `0D`                   | Valid/status и модификаторы PS/2                                                                                                                               |
| `0E`–`EF`              | NVRAM от батареи; часть старших ячеек занимает ERS                                                                                                             |
| `F0`–`FF`              | При `0C.7=0` — версии AVR, сканкоды или текущий режим ([выбор типа](#rtc-extensions)); при `0C.7=1` — 16 байтов выбранной [страницы EEPROM](#avr-eeprom)       |

Числа в первом столбце — **индексы внутри RTC**, не адреса портов Z80. Например, для чтения секунд в
обычном режиме сначала запишите `00` в `DFF7`, затем прочитайте `BFF7`; чтение порта `0000` к RTC не
относится.

AVR хранит текущее время в двоичном виде. При доступе Z80 он преобразует значения в BCD и обратно,
если бит 2 регистра 0B сброшен. В BCD каждая десятичная цифра занимает четыре бита: например, 23
записывается как 23h. Это не полный MC146818: нет полной эмуляции будильника, периодических
прерываний и 12-часового режима; физические часы загружаются как 24-часовые.

<a id="rtc-controls"></a>

### 11.2 Управление расширениями RTC

| Бит `0C` | Чтение                                                                                      | Запись                                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 0        | LED Num Lock / индикация tape out                                                           | 1 очищает журнал PS/2                                                                                                         |
| 1        | Caps LED                                                                                    | Требуемое состояние Caps LED                                                                                                  |
| 2        | Контакт разрешения записи SD: 1=можно                                                       | Не задаёт управление                                                                                                          |
| 3        | Контакт наличия SD: 1=вставлена                                                             | Не задаёт управление                                                                                                          |
| 4        | 1 означает, что AVR обновил время после предыдущего чтения `0C`; само чтение сбрасывает бит | Запись не устанавливает и не подтверждает этот флаг                                                                           |
| 7        | Последнее записанное состояние окна EEPROM                                                  | 1 переключает `F0–FF` на EEPROM; 0 возвращает выбранное расширение (версии, PS/2 или режимы). [Адресация EEPROM](#avr-eeprom) |

Чтение 0C сбрасывает флаг обновления. Запись одновременно затрагивает несколько функций: например,
02 для Caps LED также отключает окно EEPROM. Не путайте индекс RTC 0C с портом FPGA 0CBD.

0D возвращает D7=1 и активные единицей модификаторы: D0=левый Ctrl, D1=правый Ctrl, D2=левый Alt,
D3=правый Alt, D4=левый Shift, D5=правый Shift, D6=F12.

<a id="rtc-extensions"></a>

### 11.3 Версии, журнал клавиатуры и конфигурация

При выключенном окне EEPROM запись типа в любую ячейку F0–FF выбирает:

| Тип | Чтение F0–FF                                                      |
| --- | ----------------------------------------------------------------- |
| 0   | 16 байтов версии основной прошивки                                |
| 1   | 16 байтов версии загрузчика                                       |
| 2   | Журнал PS/2, по одному удаляемому байту; 0=пусто, FF=переполнение |
| 3   | F0=`modes_register`; остальные адреса возвращают FF               |

Формат версии:

```text
F0..FB: имя ASCII 12 байтов с нулевым дополнением
FC..FD: little-endian слово даты/релиза
FE..FF: little-endian CRC прошивки AVR

бит15     = официальный релиз
биты14:9  = год - 2000
биты8:5   = месяц
биты4:0   = день
```

CRC проверяет AVR-конфигурацию. Z80 ROM использует другую версию ERS. Строка не является
универсальным пофункциональным запросом возможностей FPGA. Версию ERS отдельно возвращает RST 08h.

В типе 3 `modes_register`: D0=VGA, D1=tape out, D2=Caps LED, D5:4=код растра (§4). Старое описание
лишь D4 как переключателя 60 Гц неполно. Расширение предназначено для **чтения**: запись выбирает
тип; биты режима доступны для чтения.

Тип расширения — общее состояние AVR. Чтение `F0–FF` возвращает данные выбранного типа, поэтому
для восстановления прежнего выбора приложение должно знать его из соглашения с загрузчиком
или хранить при каждой записи селектора. В C это состояние можно вести через
`bc_avr_window_select()`. Перед чтением версии явно выберите тип 0.
[rtc.h](lib/baseconf/include/baseconf/rtc.h)

Порядок чтения версии:

1. Убедиться, что `0C.7=0` (§11.2): при включённом окне EEPROM `F0–FF` — это EEPROM, а не окно
   расширений.
2. Записать тип `0` в любой индекс `F0–FF`: в обычном режиме индекс идёт в `DFF7`, данные в `BFF7`
   (нужен `EFF7.7=1`); в теневом — в `DEF7`/`BEF7` без зависимости от `EFF7.7`.
3. Прочитать 16 ячеек `F0–FF`, выставляя индекс перед каждой. При типе 2 такое чтение забирает
   байт из журнала PS/2.
4. Восстановить известный прежний тип, затем исходное состояние окна EEPROM.

Пример предполагает, что теневые порты открыты, окно EEPROM выключено, прежний тип равен 3,
а `buf` указывает на 16 доступных для записи байтов.

```asm
        ld bc,0xDEF7
        ld a,0xF0
        out (c),a
        ld bc,0xBEF7
        xor a
        out (c),a              ; тип 0: версия основной прошивки
        ld hl,buf
        ld e,0xF0
loop    ld bc,0xDEF7
        ld a,e
        out (c),a              ; индекс ячейки
        ld bc,0xBEF7
        in a,(c)               ; данные
        ld (hl),a
        inc hl
        inc e
        jr nz,loop             ; F0..FF
        ld bc,0xDEF7
        ld a,0xF0
        out (c),a
        ld bc,0xBEF7
        ld a,3
        out (c),a              ; вернуть выбор загрузчика
```

Чтобы изменить `0C.7`, перенесите из прочитанного байта только D1 (Caps Lock) и добавьте требуемый
D7. Оставьте D0 нулевым для сохранения журнала PS/2. Чтение D0 сообщает состояние Num Lock,
а запись единицы в этот бит очищает журнал. Само чтение `0C` сбрасывает флаг обновления времени D4.

<a id="avr-eeprom"></a>

### 11.4 EEPROM AVR

Запишите номер страницы EEPROM в индекс 0A, включите 0C.7, обращайтесь к F0–FF:

```text
EEPROM_address = (page_number << 4) + (RTC_index & 0Fh)
```

У ATmega128 4 КиБ EEPROM; не выходите за физический диапазон и сохраняйте прошивочные данные,
например таблицу клавиатуры. Запись постоянная, с другой задержкой и ресурсом, чем RAM. Перед
версиями/сырыми кодами выключите 0C.7. Выбранные тип расширения и страница EEPROM сохраняются в AVR
и общие для всех вызывающих программ. Если другой обработчик меняет их, выбирайте нужные настройки
заново перед обращением.

### 11.5 Постоянные настройки ERS

Следующие ячейки NVRAM сервисное ПО ERS использует для своих настроек. Их значения использует
программа ПЗУ:

| Ячейка     | ERS                                                                                                                                                                                                                                                                         |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `E7`       | D1:0 выбирают автозапуск: 0 выключен, 1 запуск `SD_BOOT.$C`, 2 запуск файла, указанного в `AUTOBOOT.INI`. D7:5 объявлены в `global_vars.a80` как таймаут; текущий `AUTORUNBOOT` их не использует                                                                            |
| `E8`       | Состояние резидента/однократного запуска, включая D7                                                                                                                                                                                                                        |
| `E9`       | Резерв текущей схемы настроек                                                                                                                                                                                                                                               |
| `EA`       | D7:4 задают задержку экранной заставки в минутах (0 отключает её); D3:0 — настройку задержки обнаружения HDD в секундах. Меню выбирает значения 0–9; это настройка ERS, не таймер FPGA                                                                                      |
| `EB`       | D7 разрешает поиск встроенной SD; D6/D5 — настройки доступа IDE master/slave (фактический поиск slave не реализован). D3:2 выбирают реальный дисковод 0–3, D1:0 — букву виртуального/рамдиска 0–3                                                                           |
| `EC`       | D7: 1=3,5 МГц, 0=7 МГц; D6 разрешает поиск SD NeoGS; D5 — автомонтирование `IMAGE.MNT`; D4 — часы в интерфейсе ERS; D3 — звук клавиш; D2 — поиск резидентной программы. D1:0: 0=1024K, 1=48K, 2=128K                                                                        |
| `ED`       | D7=1 выбирает 14 МГц, D7=0 — частоту EC.7; D6=1 выбирает загрузку из TAP, D6=0 — физическую ленту; D5 — драйвер AY-принтера в BASIC; D4=1 сохраняет текущий шрифт при сбросе; D3: 0=ATM, 1=CP866; D2 разрешает автозапуск TAP. D1:0: 0=ERS, 1=GLUK, 2=ProfROM, 3=custom ROM |
| `EE`, `EF` | CRC16 E7–ED в текущем коде, младший/старший байт                                                                                                                                                                                                                            |

Для однобитных разрешений в EB–ED значение 1 включает названную функцию, 0 выключает; исключение D4
ячейки ED явно указано в таблице. Это настройки для сервисов и процедуры сброса ERS: запись NVRAM
сама по себе не является командой немедленного переключения аппаратуры. Для изменения текущего
видеорежима, частоты или карты памяти используйте соответствующие порты. Номера дисководов 0–3
означают A–D; номера разделов FAT — другая нумерация.

Для изменения настроек ERS используйте `RST 08h,55h,02h` с пересчётом CRC. Прямая запись защищённых
ячеек может привести к восстановлению настроек по умолчанию при сбросе. Значения по умолчанию для
ED..E7: `04 82 00 00 00 00 00`. Нынешняя CRC-процедура обрабатывает все семь байтов ED..E7. В старых
описаниях указан диапазон E9..ED. ED.4=1 запрещает перезагрузку шрифта, несмотря на положительное
имя символа. ED.1:0: 0 ERS, 1 GLUK, 2 ProfROM, 3 custom ROM.

## 12. Последовательный интерфейс RS-232

AVR предоставляет часть регистров 16550 по адресам схемы Кондратьева. Передачу выполняет UART AVR, а
принятые и отправляемые байты хранятся в программных очередях FIFO: первым извлекается байт,
записанный первым. Программа Z80 сама опрашивает состояние порта. Из модемных сигналов есть CTS/RTS
— линии согласования готовности к передаче/приёму. Прерывания UART на Z80 нет; каждый доступ ждёт
AVR. FPGA выбирает регистр по A10:A8 при младшем байте EF; используйте канонические F8EF–FFEF.

DLAB — бит 7 регистра LCR (`FBEF`). Только порты `F8EF` и `F9EF` меняют назначение при его
переключении. Для настройки скорости установите DLAB=1, запишите оба байта делителя, затем верните
DLAB=0 перед передачей или приёмом данных. Остальные регистры от DLAB не зависят.

| Порт   | Чтение                                                                                      | Запись                                                                                                           |
| ------ | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `F8EF` | DLAB=0: извлечь следующий байт из очереди приёма; DLAB=1: младший байт делителя DLL         | DLAB=0: поместить байт в очередь передачи; DLAB=1: задать DLL                                                    |
| `F9EF` | DLAB=0: сохранённое значение IER; DLAB=1: старший байт делителя DLM                         | DLAB=0: сохранить IER (прерывания не реализованы); DLAB=1: задать DLM                                            |
| `FAEF` | ISR — сохранённый регистр идентификации прерывания; работа прерываний не реализована        | FCR: D0 должен быть 1; D1=1 удаляет все ожидающие байты приёма, D2=1 — передачи                                  |
| `FBEF` | Текущий LCR — формат передаваемого символа                                                  | D7=DLAB; D1:0=0/1/2/3 выбирают 5/6/7/8 бит данных; D2=0 один стоп-бит, 1 — два; D5:3 — контроль чётности (ниже)  |
| `FCEF` | Сохранённый MCR — управление модемными линиями                                              | D1 управляет RTS (1 устанавливает активный низкий уровень на выводе AVR); прочие модемные функции не реализованы |
| `FDEF` | LSR — готовность данных, состояние передатчика и ошибки (расшифровка ниже)                  | Не предусмотрена                                                                                                 |
| `FEEF` | MSR: D7=1 CD, D6=0 RI, D5=1 DSR, D4=CTS, D0=изменение CTS; чтение сбрасывает флаг изменения | Не предусмотрена                                                                                                 |
| `FFEF` | Последний записанный байт рабочего регистра                                                 | Сохранить байт; батарейного сохранения нет                                                                       |

В LCR.D5:3 двоичные значения 001/011 выбирают нечётный/чётный контроль чётности; остальные —
передачу без него. Не реализованы постоянное значение бита чётности (stick parity), передача сигнала
break, прерывания по уровню заполнения FIFO и полный механизм идентификаторов прерываний 16550.

FIFO используется всегда. AVR использует все 16 ячеек каждой очереди. При совпадении индексов
начала и конца флаги LSR отличают полную очередь от пустой. Запись в полную очередь TX
отбрасывает байт. Для поочерёдной отправки дождитесь `LSR.D5=1` перед каждым байтом, как это
делает `bc_uart_send()`. Для чтения байта дождитесь `LSR.D0=1`. Ограничивайте ожидание таймаутом.

В LSR бит D1 означает переполнение RX, D2 — ошибку чётности, D3 — ошибку формата символа,
D7 — заполнение RX не менее чем наполовину. Сброс RX FIFO очищает D1 и удаляет накопленные байты.
D5 и D6 устанавливаются вместе, когда последний байт из очереди TX передан в регистр UART AVR.
На линии в этот момент ещё может передаваться символ. Чтение MSR сбрасывает флаг изменения CTS.

Делители:

```text
DLM.bit7=0, делитель != 0:
    requested_baud = 115200 / ((DLM << 8) | DLL)

DLM.bit7=1:
    UBRR = ((DLM & 7Fh) << 8) | DLL
    actual_baud = 11059200 / (16 * (UBRR + 1))
```

Стандартный режим пересчитывается в AVR-делитель, поэтому фактическая скорость может отличаться от
запрошенной: делитель AVR принимает только целые значения. Два нулевых байта выбирают номинальный
специальный режим «256000 baud»; фактическая скорость определяется целочисленным UBRR и частотой
AVR. Для номинальных MIDI 31250 документированы DLL=15h, DLM=80h, с той же погрешностью
целочисленного делителя.

Инициализация: выставить DLAB, записать DLL/DLM, снять DLAB и задать длину слова, чётность и
стоп-биты, сбросить FIFO записью FCR=07h, установить RTS, опрашивать LSR. Сохраняйте старший
адресный байт при IN/OUT.

Источники: [`rs232.c`](avr/baseconf/trunk/src/rs232.c),
[`zports.v`](fpga/base_trdemu/trunk/z80/zports.v).

## 13. Сброс, загрузка и память ERS

### 13.1 Последовательность загрузки и виды образов

Загрузчик AVR передаёт управление рабочей прошивке AVR, содержащей конфигурацию FPGA. При полном
старте FPGA конфигурируется перед снятием сброса с Z80. Выключенный диспетчер первоначально
отображает последний банк Flash во все окна. Сервис page0 начинает с 0000, создаёт обе карты,
инициализирует RST/NMI, применяет настройки, палитру/шрифт, выбирает целевое ПЗУ либо меню ERS.

Не смешивайте два обновляемых образа:

- `zxevo_fw.bin` — программа AVR с конфигурацией FPGA; устанавливается через загрузчик AVR.
- `rom/zxevo_fe.rom` — 512 КиБ Z80 Flash, собранные из BASIC, DOS, ERS, CP/M, GLUK, ProfROM и
  пользовательской области.

Перехват портов FE требует соответствующего FE ROM. Замена только одного слоя может сохранить внешне
нормальную загрузку, но нарушить эмуляцию дисков или сервисы ПЗУ.

### 13.4 Выбор ПЗУ при сбросе и резидент

ED.1:0 выбирают ERS, GLUK, EVO ProfROM или пользовательский набор 64 КиБ. Удержание 0 при сбросе
принудительно выбирает ERS и очищает активацию резидента/автозапуска. Исходник обрабатывает также
клавиши выбора BASIC/DOS/ меню и вход в CMOS setup при нескольких нажатых клавишах. Это политика
reset service, не дополнительные аппаратные векторы сброса.

GLUK/custom ожидают соглашение входа около 3D2D и `NOP; RET` в 3D2F. Для запуска ProfROM короткий
код переключения страниц копируется в RAM и исполняется оттуда, чтобы смена ROM не заменила саму
исполняемую команду. Заменяющее ПЗУ должно соблюдать соглашения страниц/входа выбранной конфигурации
либо иметь собственный reset service. Резидент Honey Commander использует выделенную страницу
старшей памяти, опкод перехода, контрольную сумму и завершающую сигнатуру. Условия запуска задаёт
`CMP_REZIDENT` в page0; отдельного общего API автозапуска приложений нет.

## 14. Взаимодействие AVR/FPGA и разработка прошивок

### 14.1 Разделение обязанностей

FPGA реализует шины Z80, арбитраж RAM, страницы, видео, тактирование, регистры ввода, SD SPI и
логику, которая удерживает CPU в WAIT до ответа AVR. AVR обслуживает PS/2, перевод клавиатуры,
механические входы, считывание магнитофонного сигнала, RTC/NVRAM, UART, ATX/reset, загрузку FPGA.
Приложения Z80 обращаются к AVR обычно через RTC/UART. Следующая внутренняя SPI-карта **не является
пространством I/O-портов Z80**.

<a id="avr-spi"></a>

### 14.2 Внутренний SPI-протокол

При `spics_n=1` передаётся номер регистра и читается статус; при низком CS идёт обмен данными,
восходящий фронт фиксирует многие операции. Этот фронт также сбрасывает выбор регистра в ноль,
поэтому перед новой транзакцией выберите его заново. Значение статуса запоминается на переходе CS из
0 в 1: D7=1 означает, что Z80 ждёт чтения, D7=0 — записи; D0=1 означает ожидающее обращение к RTC,
D1=1 — к UART.

| SPI-регистр            | Назначение                                                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `00`                   | Начальный/игнорируемый                                                                                                                 |
| `10`                   | Сдвиг 40 битов клавиатуры                                                                                                              |
| `11`                   | Применить ранее переданные через `10` 40 битов как новую матрицу клавиатуры; действие выполняется при переходе CS 0→1                  |
| `20`, `21`, `22`, `23` | Мышь X/Y/кнопки, Kempston-джойстик                                                                                                     |
| `30`                   | Запрос сброса Z80 по фронту CS                                                                                                         |
| `40`                   | Если Z80 читает — AVR передаёт ответ; если Z80 пишет — AVR получает записанный байт. Переход CS 0→1 завершает обращение и снимает WAIT |
| `41`                   | Чтение RTC-индекса, выбранного Z80                                                                                                     |
| `42`                   | Чтение сохранённого номера UART по A10:A8                                                                                              |
| `50`                   | D0 VGA, D1 спад запроса NMI, D2 tape in, D3 выбор tape out, D5:4 растр                                                                 |
| `60`                   | Данные обмена SD                                                                                                                       |
| `61`                   | Арбитраж SD: D7 запрос/состояние lock, D0 CS_n AVR                                                                                     |

Для SD AVR запрашивает lock при высоком CS_n, ждёт выдачи после отпускания карты Z80, затем работает
с lock. Освобождение: поднять CS_n при установленном lock, затем снять lock. Первый прочитанный байт
после получения доступа не определён как корректный принятый байт.

Для WAIT определите источник/направление по статусу, прочитайте адрес источника, обменяйтесь данными
через 40 и завершите транзакцию. Всё это время Z80 ждёт. Новому AVR-устройству нужны соответствующая
маршрутизация запросов FPGA и обработчик AVR; один новый `case` в C не создаёт порт Z80.

### 15.1 Улучшенный контроллер прерываний в ветке `newirq`

Порты `14BD`–`16BD` относятся к отдельной ветке
[`fpga/base_trdemu/newirq`](fpga/base_trdemu/newirq/): адреса декодируются в `z80/zports.v`, логика
контроллера находится в `z80/zint.v`. В основной ветке
[`fpga/base_trdemu/trunk`](fpga/base_trdemu/trunk/) этих регистров нет; её `zint.v` формирует
кадровый импульс.

У `newirq` есть отдельный проект Quartus и цель `top.rbf` в
[`quartus/Makefile`](fpga/base_trdemu/newirq/quartus/Makefile). Сборщик standalone-конфигурации
указывает на `fpga/base_trdemu/trunk/quartus`; штатная упаковка прошивки `newirq` не выбирает.

Реализация `newirq` неполная. Например, автосброс запросов обозначен в `zint.v` как TODO и
фактически отключён. Таблица ниже передаёт описание интерфейса из руководства; перед использованием
конкретной функции сверяйтесь с исходниками собранной FPGA.

| Порт   | Документированное действие                                                                                                                                                                                                                                                                  |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `14BD` | D7=1 включает улучшенный контроллер, 0 — традиционный кадровый INT. D2=1 разрешает ZXBUS выдавать вектор при подтверждении прерывания; D1=1 разрешает вектора внутренних источников; D0=1 автоматически снимает подтверждённый внутренний запрос (только при D1=1). После сброса все биты 0 |
| `15BD` | Разрешение внутренних прерываний; D0 VBLANK; D7 при записи set/reset, при чтении 0                                                                                                                                                                                                          |
| `16BD` | Ожидающие внутренние запросы; D0 VBLANK; D7 при записи set/reset, при чтении 0                                                                                                                                                                                                              |

VBLANK — запрос в начале кадрового гашения, то есть после видимой части кадра. «Разрешение» в `15BD`
означает, что соответствующий ожидающий запрос может вызвать INT; сам запрос хранится отдельно в
`16BD`. Запросы фиксируются и при разрешении удерживают INT. Внутренние имеют приоритет перед
внешними. Внутренние вектора по убыванию приоритета:

| Бит | Вектор | Инструкция IM 0 | Источник |
| --- | ------ | --------------- | -------- |
| 6   | CF     | RST 08h         | Резерв   |
| 5   | D7     | RST 10h         | Резерв   |
| 4   | DF     | RST 18h         | Резерв   |
| 3   | E7     | RST 20h         | Резерв   |
| 2   | EF     | RST 28h         | Резерв   |
| 1   | F7     | RST 30h         | Резерв   |
| 0   | FF     | RST 38h         | VBLANK   |

Это **байты векторов прерывания**, не номера ERS-функций. Резервные биты не означают реализованные
устройства. Автоочистка требует внутренних векторов; руководство не рекомендует полагаться на неё в
IM 1 из-за потери информации об источнике. Активное внутреннее прерывание блокирует подтверждение
внешнего. Внешнюю векторизацию разрешают только с подходящими устройствами; вектор внешнего запроса
по умолчанию C7 (`RST 00h`).

Таблицы руководства называют D7 переключателем set/reset, но не объясняют однозначно, какое значение
выбирает установку, а какое — сброс битов. Перед записью регистров разрешения и состояния проверьте
это по исходникам именно той прошивки, где установлен улучшенный контроллер.

## 17. ROM и RST API

### 17.1 Соглашение вызова и условия работы

ERS расширяет RST 08h функциями, байты которых следуют за инструкцией:

```asm
        rst 0x08
        db 0x4D            ; номер функции VERSION

        ld h,0x09          ; индекс года RTC
        rst 0x08
        db 0x55,0x01       ; функция CMOS_RW, подфункция READ_CMOS; результат A=L
```

Вызов состоит из `RST 08h` и следующего за ним байта номера функции. Для групповых функций после
него записывается ещё один байт — номер подфункции:
`RST 08h → функция → подфункция → следующая команда`. Это данные в коде программы, которые читает
ERS. После возврата выполнение продолжается после последнего байта вызова.

В первом примере `4Dh` выбирает функцию `VERSION`, поэтому за ним сразу идёт следующая команда. Во
втором `55h` выбирает группу `CMOS_RW`, а `01h` — её подфункцию `READ_CMOS`; регистр H содержит
индекс RTC. Результат чтения — в A и L.

Для MATH, COM_DEV, COM_FAT, MOUNTER и CMOS_RW следующий байт задаёт номер подфункции. Вызов драйвера
через COM_DEV может читать ещё один байт. POS_FILES получает дополнительную операцию из регистра A.
Число байтов после RST должно точно соответствовать выбранному вызову, иначе после возврата
программа начнёт исполнение не с той инструкции.

Публичный API ERS использует один вектор `RST 08h`; номера функций идут следующими байтами в коде.
Внутренние межстраничные вызовы ERS также используют `RST 20h` и `RST 30h`; они описаны в §17.7.

Стартовая программа ПЗУ должна предварительно установить ERS. Кроме того, страница, включённая по
адресу 0000, должна содержать короткие процедуры входа в сервис и возврата из него. Такие
процедуры-переходники в исходниках и английском описании называются stubs.

В полной ERS-сборке `ROM_BAS48` — BASIC 48 из Spectrum 128 ROM 1 с изменениями Evolution. Вектор
`0008h` содержит `NOP; JP RST8_CMP`. Эта процедура проверяет байт после `RST 08h` и передаёт ERS
команды `40h–6Fh`; документированные публичные функции занимают диапазон `40h–57h`. Вызовы BASIC для
AY-принтера используют функции ERS `40h–43h`. В ROM также включены процедуры клавиатуры и токенов
режима 128K, перечисленные в §13.2. В `ROM_BAS128` собран стандартный BASIC 128: адрес `0008h`
находится внутри команды задержки при сбросе, отдельного обработчика `RST 08h` там нет. Стандартные
ROM-слоты `ROM_BAS48_STD` (`18h`), `ROM_BAS128_STD` (`19h`) и `ROM_BAS48_128` (`1Ah`) также не
содержат диспетчера ERS. Исходный 48K ROM использует `RST 08h` для ошибок BASIC.

Команда `RST 08h` передаёт CPU на адрес `0008h` в странице, отображённой в окно 0. В `ROM_RST83` по
этому адресу находится `JP $` — переход на ту же команду, который зацикливает CPU. Поэтому вызов
должен начинаться со страницы, где по `0008h` установлен входной переходник: например,
`services.rom` содержит `NOP; JP DOS2RST8`, а `ROM_BAS48` — `NOP; JP RST8_CMP`. Переходник
подготавливает состояние вызова и передаёт его диспетчеру ERS в `ROM_RST83`.

Входные процедуры сохраняют регистры CPU, карту памяти и состояние прерываний. Затем они включают
физическую RAM FF и передают управление сервисному ПЗУ. Копии регистров хранятся в ячейках с именами
RREG_*; функции читают оттуда параметры и записывают туда возвращаемые значения. Код, который
выполняет это преобразование между вызовом приложения и внутренней процедурой, называется обвязкой
вызова (wrapper).

Во время работы ERS временно меняет окна памяти и обычно выбирает 7 МГц. При выходе он
восстанавливает сохранённое состояние, кроме изменений, запрошенных функцией. Некоторые процедуры
умеют обращаться к буферу через сохранённую карту вызывающей программы. Другие, например загрузка
шрифта, читают адрес напрямую в своей текущей карте; это ограничение указано отдельно.

Размещайте буферы в доступной RAM приложения, вне страниц ERS. Код с RST и байтами функций также
должен оставаться доступным для чтения. Нельзя начинать второй вызов ERS, пока не завершился первый:
он использует те же RREG, стеки и состояние файла/каталога/раздела. Такой сервис называют
нереентерабельным. Поэтому обработчик прерывания или вложенного NMI не должен вызывать ERS поверх
уже выполняющегося вызова.

Если регистр не указан среди результатов функции, обвязка обычно сохраняет его прежнее значение.
Изменения флагов, буферов, позиции файла и настроек сервиса описываются для каждой функции отдельно.
Отсутствие возвращаемого значения не означает, что функция ничего не меняет. Флаг переноса CF нельзя
считать универсальным признаком ошибки: используйте соглашение конкретного вызова.

В C вызов `bc_ers_set_profile()` сообщает библиотеке, какой контекст ПЗУ подготовило приложение.
Обёртки `bc_ers_*` используют тот же `RST 08h` и те же требования к памяти. Для операций с
накопителями проверяйте и `bc_status_t`, и поле результата прошивки. Например, после
`BC_OK` от `bc_ers_device_find()` поле `found` показывает, найден ли раздел.
[rom.h](lib/baseconf/include/baseconf/rom.h) · [ers.h](lib/baseconf/include/baseconf/ers.h)

Диспетчер маскирует номер `3Fh` и индексирует таблицу из **24 элементов** 40h–57h без общей проверки
границ. Допустимы только назначенные функции. Диапазон 40h–7Fh содержит и неназначенные номера.
Неизвестные номера подфункций также недопустимы.

Источники: [`rst8.a80`](rom/page3/source/rst8.a80), [`services.a80`](rom/page0/source/services.a80),
[`rst8service.a80`](rom/page5/source/rst8service.a80),
[`nmi_service.a80`](rom/page5/source/nmi_service.a80).

| `52`     | `SORT_FINDFILES`          | Сортировка внутренних результатов поиска, без указателя буфера [Подробнее](#rst-storage).                                                                                                   |
| `53`     | `MOUNTER`                 | Номер подфункции следующим байтом образов/дисководов 00–0B [Подробнее](#rst-storage).                                                                                                       |

Для 4D BCDE=00006101h означает 0.61.01. A.bit0=1 означает FE с аппаратной поддержкой эмуляции, 0 —
прежний программный вариант. A.bit7 показывает несоответствие FPGA/ROM, обнаруженное пробной
записью/чтением 13BD с последующим восстановлением. Это ограниченная проверка, не полное сравнение
версий или возможностей FPGA.

Старый PDF ERS называет 4E/4F резервом. `rom/c/ers.h` сохраняет `_BIOS=4F` и не содержит актуальных
вызовов файлового браузера. Фактически выполняемую функцию определяет таблица CODE_TABL в ПЗУ.
`EXT_FILE_BROWSER` читает дополнительный байт, устанавливает флаги внешнего браузера и запрета
браузера по NMI, затем переходит к открытию меню. Прошивка не определяет для этого входа соглашение
о возврате в программу или о передаче выбранного файла.

### 17.3 Перехваты BASIC, окна, строки, палитра и шрифты

**Принтер/лента 40–45.** Модифицированный BASIC вызывает эти функции из штатных точек входа печати и
загрузки ленты. Такое подключение называется перехватом (hook). Функциям нужны переменные и
состояние, подготовленные BASIC, а также настройки ERS; их нельзя считать самостоятельным драйвером
для произвольной программы. При выключенном принтере 41 воспроизводит флаги `LD A,B; CP 3; SBC A,A`;
у 43 в контексте BASIC COPY есть путь с результатом B=B0h. Прямой вызов 43 при включённом
AY-принтере печатает ZX-экран из `4000h` и возвращается в приложение, сохраняя буфер печати BASIC.

При успешной загрузке эмулятор увеличивает IX на размер скопированного блока, обнуляет DE и
устанавливает флаги результата загрузки. Когда эмуляция выключена, вызов воспроизводит поведение
исходного загрузчика, включая C=A и флаги `CP A`. Точное соглашение флагов/альтернативных регистров
задаёт место вызова BASIC в [`tape.a80`](rom/page5/source/tape.a80). Одних IX/DE недостаточно для
выбора TAP и текущего блока: сначала загрузите его через ERS.

**Описатель окна 46.** Смещения в таблице шестнадцатеричные. Двухбайтные значения записываются
младшим байтом вперёд (little-endian). Координаты и размеры описателя задаются в знакоместах.

| Смещение   | Размер | Поле                                                                                                                                                                                         |
| ---------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `00`, `01` | По 1   | X, Y                                                                                                                                                                                         |
| `02`, `03` | По 1   | Высота, ширина                                                                                                                                                                               |
| `04`, `05` | По 1   | Цвет окна, курсора                                                                                                                                                                           |
| `06`       | 1      | D7=1 рисует нижний заголовок, D6=1 убирает рамку, D5=1 рисует верхний заголовок; D4=0 выводит текст по адресу из `0C`, D4=1 пропускает его; D3=1 выбирает список файлов, D3=0 открывает меню |
| `07`       | 1      | Позиция/управление; при D7=1 слово по смещению 08 содержит адрес переменной номера пункта; при D6=1 слово по 0A содержит адрес переменной числа пунктов                                      |
| `08`       | 2      | При D7 байта `07`=0 — сам номер текущего пункта; при D7=1 — адрес двухбайтной переменной с этим номером                                                                                      |
| `0A`       | 2      | При D6 байта `07`=0 — само число пунктов; при D6=1 — адрес двухбайтной переменной с этим числом                                                                                              |
| `0C`       | 2      | Адрес текста                                                                                                                                                                                 |
| `0E`       | 2      | Таблица обработчиков пунктов                                                                                                                                                                 |
| `10`       | 2      | Список активных зон мыши                                                                                                                                                                     |
| `12`       | 2      | Список горячих клавиш                                                                                                                                                                        |

Зона мыши — прямоугольная область, которой назначена горячая клавиша. Её запись занимает шесть
байтов: резерв, X, Y, высота, ширина, код клавиши. Вызов рисования окна не предоставляет публичного
доступа к внутренним процедурам выбора пунктов меню. Сначала установите видеорежим и нарисуйте
окно. Передавайте его описатель в IX при каждом вызове 47, который использует коды 01 или 03,
и при каждом вызове 49 или 4A. Храните описатель в RAM по адресу 4000–7FFFh, чтобы он оставался
доступен при переключении других окон памяти. Вызов 48 использует сохранённую позицию курсора.

**Управление строкой 47.** Ноль завершает, обычные печатные байты — символы. Процедура вывода на
ZX-экран использует шрифт 6×8, текстовый режим — аппаратные знакоместа:

| Последовательность | Действие                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------ |
| `01`               | Вернуть позицию печати к началу области текста текущего окна; содержимое окна не очищается |
| `03`               | Центрирование следующих печатных символов в ZX-окне; в текстовом режиме игнорируется       |
| `09,n`             | Продвижение на n знакомест                                                                 |
| `0D`               | Новая строка окна                                                                          |
| `16,y,x`           | Позиция, **Y раньше X**; на ZX координаты в пикселях, в текстовом режиме в знакоместах     |
| `17,c`             | Цвет; FF сохраняет атрибуты приёмника                                                      |

Нельзя подменять набор реализованных кодов полным PRINT BASIC. Внутренние особые формы сообщений
также не являются общим внешним форматом.

**Палитра 56.** HL — 16 байтов инверсного ATM `grbG00RB` (§5.4), не RGB тройки; A=0 выбирает
встроенную таблицу. Процедура временно разрешает запись палитры и ждёт кадровой синхронизации. Для
RGB444 и ULAplus используйте соответствующие аппаратные регистры. Классическое
сохранение/восстановление палитры не сохраняет пользовательскую RGB444-таблицу.

**Шрифт 57.** Встроенные ресурсы упакованы. В текущем коде A=2 тоже передаёт HL прямо в UNPACK,
затем копирует 2048 распакованных байтов в RAM шрифта. Пользовательские данные должны иметь тот же
формат сжатия (в сборке MHMT `-mlz`), а источник — быть доступным в фактической карте процедуры. PDF
указывает диапазон 4000–FFFF, но не поясняет распаковку. В этой ветви нет восстановления карты
приложения для чтения источника. Поэтому адрес, доступный до вызова, может указывать на другие
данные внутри процедуры. Для произвольных сырых шрифтов используйте BF.2 из §5.6.

Источники: [`window.a80`](rom/page5/source/window.a80),

[`addons.a80`](rom/page5/source/addons.a80), [`addon1.a80`](rom/page5/source/addon1.a80),

### 17.4 Режимы и математика

**4B SET_MODE.** В PDF и C-заголовке описаны параметры видео `режим|08h`, частоту 10/20/30, память
40/80/C0 для 48K/128K/1024K. Нынешний ISET_MODE делает следующее:

| Поле запроса  | Реальное действие                                       |
| ------------- | ------------------------------------------------------- |
| A=0           | Вернуть сохранённое значение TEK_MODES                  |
| A2:0≠0        | Заменить сохранённые видеобиты xx77                     |
| A2:0=0        | Не менять видео; D3 как разрешение смены не проверяется |
| A5:4=1/2/3    | Сохранённая частота 3,5/7/14 МГц                        |
| A7:6=1 (`40`) | Сохранённый режим **1024K**                             |
| A7:6=2 (`80`) | Сохранённый режим **48K**                               |
| A7:6=3 (`C0`) | Сохранённый режим **128K**                              |

Ненулевой запрос целиком сохраняется в TEK_MODES. Актуальная конфигурация регистров при этом не
считывается и не объединяется с запросом. При смене памяти процедура возвращается, не обновив
сохранённое значение A, которое приложение получит после вызова. Поскольку нулевые видеобиты
означают «не менять», описанный в руководстве запрос режима 0 через 08h не включает 320×200.
Видеоконстанты define.a80 и заголовка также местами расходятся с числовыми кодами ATM. Для точной
смены используйте аппаратные порты либо предварительно исправьте реализацию этой функции в ROM.
Настройки временные, без записи CMOS.

**4C MATH: параметры и результаты, которые получает приложение:**

| Номер подфункции следующим байтом | Операция                    | Вход                            | Выход                                                       |
| --------------------------------- | --------------------------- | ------------------------------- | ----------------------------------------------------------- |
| `00`                              | Беззнаковое деление 16 бит  | **HL** делимое, DE делитель     | DE частное                                                  |
| `01`                              | Умножение 16×16             | BC, DE множители                | BCDE произведение                                           |
| `02`                              | Беззнаковое деление 32 бит  | BCDE делимое, BC′DE′ делитель   | BCDE частное, BC′DE′ остаток                                |
| `03`                              | Умножение 32×16             | BCDE множимое, **HL** множитель | BC′DE′BCDE (результат занимает перечисленные восемь байтов) |
| `04`                              | Десятичная строка из 32 бит | BCDE число, HL приёмник         | Нуль-терминированная строка                                 |
| `05`                              | То же 16 бит                | DE число, HL приёмник           | То же                                                       |
| `06`                              | То же 8 бит                 | E число, HL приёмник            | То же                                                       |

Слева в объединённом имени регистров — старший байт. Для **каждого** преобразования выделяйте **11
байтов**: процедура копирует столько байтов и для коротких значений. Значимые данные заканчиваются
первым нулём; хвост за ним не является результатом. Для деления на ноль нет документированного
возврата ошибки; приложение должно исключить нулевой делитель до вызова.

Старые комментарии умножения содержат прежние имена регистров. Для таблицы выше использованы
инструкции чтения и записи сохранённых регистров в процедурах `.X*`. BC-делимое divide16 и два
32-битных множителя из PDF не соответствуют коду передачи параметров.

### 17.5 Устройства, FAT и образы

Все эти функции работают с одним общим состоянием: выбранным разделом, позицией каталога, текущим
файлом, кешем кластеров и буферами ERS. Открытие другого файла заменяет состояние предыдущего;
отдельных независимых идентификаторов открытых файлов здесь нет. Перед обращениями к FAT и образам
найдите устройства и выберите раздел.

#### Менеджер устройств: 50, следующий байт — подфункция

| Подфункция | Имя              | Параметры и результат                                                                                                                                        |
| ---------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `00`       | `DEVFIND`        | Поиск/инициализация устройств и разделов; D=текущий, E=число, A=тип 0 FAT12 / 1 FAT16 / 2 FAT32; CF=1 ничего нет                                             |
| `01`       | `SET_VOL`        | A=номер раздела с нуля; CF=1 неверный номер; меняет текущий FAT-контекст                                                                                     |
| `02`       | `KOL_VOL`        | Текущий раздел/число/тип, как при поиске                                                                                                                     |
| `03`       | `GET_FNDVOLUME`  | HL=приёмник 256-байтной таблицы разделов                                                                                                                     |
| `04`       | `TO_DRV`         | Третий байт после RST, 00–04, задаёт функцию выбранного блочного драйвера                                                                                    |
| `05`       | `SET_DEVICE`     | Внутренняя настройка device/head/LBA меняет B внутри сервиса, но не сохраняет результат для возврата приложению; используйте вызов драйвера                  |
| `06`       | `CONTROL_SD`     | Проверяет наличие SD; на выходе A: D0=1 встроенная карта доступна, D1=1 доступна NeoGS SD. При обнаружении смены носителя обновляет общее состояние сервиса  |
| `07`       | `COMHDDNEX`      | Третий байт — функция Nemo; HL буфер, BCDE начальный LBA, A число секторов, A′ бит master/slave; особенности ниже                                            |
| `08`       | `FREINIT_VOL`    | Переинициализация раздела; процедура не имеет полноценной передачи параметров из сохранённых регистров приложения; используйте обычный поиск и выбор раздела |
| `09`       | `SET_SECTOR_NUM` | HLBCDE=48-битный сектор, HL старшая пара; сохраняет NUMSEC_LBA48                                                                                             |

Функции драйвера: 00 INIT, 01 STATUS, 02 READ, 03 WRITE, 04 READID. Для `07/02` и `07/03`
параметры: HL=буфер, A=число 512-байтных секторов, BCDE=32-битный LBA, бит 0 A′=диск
(0 master, 1 slave). Это значение **не** ID устройства из таблицы томов (`04/05` для Nemo в
текущей сборке). Перед вызовом выберите Nemo-раздел через `SET_VOL`: текущий драйвер READ/WRITE
берёт ATA device/head из выбранного тома, поэтому A′ сам по себе не переключает master/slave.
Нулевой A означает 256 секторов и требует буфер 131072 байта; для обычных буферов используйте
ненулевое число секторов. WRITE изменяет данные на выбранном устройстве.

Этот контракт следует из `rom/page5/source/fat/nemo_drv.a80` и
`rom/page5/source/fat/dev_drv.a80`. После вызова A содержит статус: 0 успех, 1 таймаут, 6 ошибка
команды, 7 обнаружен CD/DVD. Внешний
вызов возвращает A/HL/DE/BC, но не всегда обновляет сохранённый F, поэтому CF нельзя использовать
как признак успеха. В текущем драйвере BCDE сохраняет начальный LBA, а HL указывает за последним
переданным байтом (при частичной ошибке — за последним фактически переданным). `BC_OK` обёртки
означает лишь возврат из ERS; проверяйте статус A. У SD и опциональных драйверов детали INIT/STATUS
свои. Сохранение 48-битного номера через 09 не превращает все пути передачи в полнофункциональный
ATA48 API.

Таблица разделов — записи по восемь байтов: +0 ID устройства, +1 master/slave или 0 для SD, +2 FAT
type 0/1/2, +3..6 начальный сектор little-endian, +7 резерв. Копия 256 байтов содержит и метаданные
за заполненными записями; обрабатывайте количество записей, которое вернула процедура; размер
таблицы — 32 позиции. Разделы не равны буквам дисководов A–D. Старые описания противоречиво
указывают предел 16/26; ориентируйтесь на ограниченную таблицу и результат поиска.

ID из `nums_devices.a80`:

| ID      | Устройство                              |
| ------- | --------------------------------------- |
| `00–03` | FDD A–D; не обычные FAT-драйверы поиска |
| `04/05` | Nemo master/slave                       |
| `06/07` | SMUC master/slave                       |
| `08/09` | DivIDE master/slave                     |
| `0A/0B` | Profi master/slave                      |
| `0C/0D` | ATM Turbo 2+ master/slave               |
| `0E`    | NeoGS SD                                |
| `0F`    | Встроенная/Z-controller SD              |
| `10`    | SL811 USB Flash; в сборке USB_ENABLE=0  |

Объявленный ID не доказывает наличие интерфейса/разрешённого драйвера. Текущий поиск пробует Nemo
master, опциональную NeoGS SD и встроенную SD; USB исключён из сборки.

| `09`       | `READ_FILE`     | A=число секторов по 512, HL=приёмник; CF=1 при конце файла или ошибке; возвращаемый HL продвигается по мере чтения                                                                                           |
| `0A`       | `INIT_TEKDIR`   | Внутренняя таблица кластеров каталога; не общий вызов приложения                                                                                                                                             |
| `0B`       | `POS_FILES`     | A=операция ниже, BC=аргумент/результат позиции                                                                                                                                                               |
| `0C`       | `ROOTDIR`       | Корневой каталог текущего раздела                                                                                                                                                                            |

FIND_NAME завершает имя байтом меньше 21h, включая пробел. Это поиск короткого имени, не поиск
произвольного длинного имени с пробелами. Маска расширений — группы ровно по три байта, например
`"TRDSCLFDI",0`; короткие расширения дополняются. Поиск сохраняет каталоги и пропускает запись `.`.

POS_FILES: A=00 сохранить позицию, 01 восстановить, 02 найти первую допустимую, 03 отмотать на B
файлов назад, 04 на B вперёд, 05 посчитать допустимые, 06 выбрать допустимый порядковый номер BC, 07
вернуть его. Удалённые записи и дополнительные записи для частей длинного имени не считаются
допустимыми; физическая позиция записи в каталоге FAT и порядковый номер допустимого файла
различаются.

Обычный порядок: поиск устройств → выбор раздела → поиск/выбор файла → открытие → чтение секторов.
Размер последнего значимого фрагмента определяйте по полю размера файла в записи каталога. Функция
не возвращает число прочитанных байтов; это не API записи файлов FAT.

52 SORT_FINDFILES сортирует **существующие внутренние** результаты, сначала каталоги, затем файлы,
по таблице порядка символов ПЗУ. Произвольный массив приложения не принимает. Буфер
поиска/сортировки — физическая FC, инверсное значение порта 03.

#### Монтировщик: 53, следующий байт — подфункция

Ниже приведён **актуальный порядок TAB_MOUNTER**. Старый PDF и C-header указывают другую
последовательность:

| Подфункция | Имя             | Параметры / результат                                                                                   |

| `00`       | `OPEN_MOUNT`    | A=диск 0–3; монтировать текущий FAT-файл; для работы непосредственно с файлом поддерживается формат TRD |

Старый PDF вставляет отсутствующую функцию в 06 и сдвигает следующие; ers.h называет 09
MOUNT_RAMDISK. В этих исходниках отдельная процедура монтирования рамдиска выключена или
закомментирована. Не все операции записывают код ошибки в возвращаемые регистры. Проверяйте
состояние соответствующими запросами; не считайте CF единым признаком успеха всех функций.

В текущей реализации `CMP_DRIVE` вычисляет смещение описателя как `4 × диск`.
Размер описателя составляет 64 байта, поэтому для дисков B–D используйте маску `GET_VIRT_BITS`.

Описатель примонтированного образа, 64 байта; смещения hex:

| Смещение | Размер | Поле                                                                                                                         |
| -------- | ------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `00–1F`  | 32     | Запись каталога FAT: имя, атрибуты, кластер, размер                                                                          |
| `20`     | 1      | Внутренний флаговый байт; стабильная побитовая схема для приложений не определена                                            |
| `21`     | 1      | Внутренний номер типа файла, определённый по расширению; это не текст расширения и не ID устройства                          |
| `22`     | 1      | Число кластеров между сохранёнными позициями цепочки FAT; используется для быстрого поиска сектора образа, не размер сектора |
| `23`     | 1      | Файловая система раздела с образом: 0=FAT12, 1=FAT16, 2=FAT32                                                                |
| `24`     | 1      | Номер раздела в таблице менеджера устройств, с нуля; не буква дисковода                                                      |
| `25`     | 2      | Адрес драйвера устройства образа                                                                                             |
| `27`     | 2      | Сохранённый адрес драйвера выбранного раздела                                                                                |
| `29`     | 1      | Дисковод, которому назначен образ: 0=A, 1=B, 2=C, 3=D                                                                        |

возвращает снимок внутренних описателей: изменение полученной копии не монтирует образ и не меняет
дисковод. Для этого используйте функции монтировщика; не создавайте описатель вручную.

Адрес драйвера указывает на код конкретной сборки ПЗУ. Его нельзя сохранять как постоянный
идентификатор и вызывать после смены ROM. Дополнительные таблицы путей и кеши дисковода не входят в
возвращаемые 256 байтов.

### 17.7 Остальные вектора RST и межстраничные вызовы

Инструкция RST вызывает фиксированный адрес CPU. Какая процедура находится по этому адресу, зависит
от страницы ROM/RAM, включённой в окно 0. Поэтому одинаковая инструкция RST в разных картах памяти
может выполнять разные действия.

| Вектор / вход          | Действие в соответствующем сервисном контексте                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| `0000`                 | Reset в ROM_ERS; в установленном RAM-сервисе — JP CALL2PAGE                                         |
| `0008`                 | Сервис через совместимые процедуры входа в ROM; ошибка BASIC в немодифицированном ROM               |
| `0010`, `0018`, `0028` | Нового универсального API Evolution нет; внутренние сервисные страницы ROM могут содержать заглушки |
| `0020` (RST 20h)       | Внутренний CALL2RAMPAGE в страницах, предоставляющих этот вектор                                    |
| `0030` (RST 30h)       | Внутренний CALL2PAGE в соответствующих страницах                                                    |
| `0038`                 | Вход IM 1/кадрового INT; сервисные страницы могут содержать только EI; RET                          |
| `0066`                 | NMI, не инструкция RST; аппаратный NOP и подстановка FF                                             |

Внутренние процедуры ERS используют следующий формат межстраничного вызова:

```asm
        rst 0x30           ; ROMCALL, только при установленной сервисной среде
        dw target_address
        db rom_port_value

        rst 0x20           ; RAMCALL, с тем же ограничением контекста
        dw target_address
        db inverted_ram_page
```

CALL2PAGE сохраняет номер текущей страницы во внутреннем стеке ERS, включает целевую страницу в окно
0 и вызывает указанный адрес. После RET вызываемой процедуры возвращается прежняя страница. Вариант
для RAM переключает страницу через x7F7.

Эти процедуры изменяют собственный код и используют внутренний стек страниц ERS. Они работают только
при установленной сервисной среде. Приложение, которое заменило обработчики или заняло рабочую
память ERS, должно реализовать свои межстраничные вызовы.

Внутренние точки входа ROM_RST83: 0014 переключает страницу, 001C служит DOS-входом, 0024 — входом с
page0, 002C продолжает диспетчер, 0034 продолжает NMI. ROM_RST81:0040 устанавливает среду RST/NMI,
ROM_MAINMENU:0101 распаковывает меню в RAM. Это точки интеграции конкретной сборки прошивки, не
стабильные публичные функции.

Имя `_BIOS` и константы адресов переходов от 0100 для устройств, клавиатуры и выделения памяти в
заголовке не создают отдельный публичный RST BIOS в текущем CODE_TABL. У ATM CP/M собственный BIOS с
переключением страниц памяти в [`rom/atm_cpm/source`](rom/atm_cpm/source/). Его соглашения не
следует смешивать с ERS-селекторами и restart-опкодами IM 0 улучшенного контроллера прерываний.
