# rom/page5 — RST 8 Service (EVO Reset Service)

Сервисное ПЗУ компьютера **ZX Evolution / PentEvo**: набор из пяти 16‑килобайтных страниц ПЗУ,
который даёт системе

- обработчик `RST 8` (BIOS сервиса) и API для софта (DOS, меню, загрузчики, пользовательские
  программы);
- меню **MAGIC** по кнопке NMI — «волшебное меню» с настройками, файловым браузером и отладчиком;
- подсистемы: менеджер устройств, драйвер FAT12/16/32, монтировщик образов TRD/SCL/FDI/TAP, рамдиск,
  эмуляция магнитофона, принтер через AY, движок окон/текстового вывода, работа с CMOS и шрифтом;
- упакованный образ **главного меню ERS** (страница `ROM_MAINMENU`), которое распаковывается в ОЗУ
  при сбросе.

Сборка: `source/build.sh` → `../rst8service.rom` и `../rst8service_fe.rom` (80 Кбайт = 5 страниц).

Смежный документ: [`../page0/README.md`](../page0/README.md) — стартовая сервисная страница, которая
инициализирует этот сервис и решает, что загружать после сброса.

## 1. Место в прошивке

### 1.1. ROM-страницы

Нумерация страниц ПЗУ задаётся порядком `SETVAR` в `rom/global_vars.a80` (проверено по
`source/rst8service.lst`):

| Константа          | №     | Содержимое в сборке ERS                                                         | Источник                                             |
| ------------------ | ----- | ------------------------------------------------------------------------------- | ---------------------------------------------------- |

| `ROM_BAS128`       | 1     | BASIC 128                                                                       | `rom/page2`                                          |
| `ROM_DOS`          | 2     | EVO‑DOS / NEO‑DOS                                                               | `rom/page1`                                          |
| `ROM_BAS48`        | 3     | BASIC 48                                                                        | `rom/page3`                                          |
| `ROM_EMPTY`        | 4     | пустая (0xFF)                                                                   | —                                                    |
| **`ROM_MAINMENU`** | **5** | распаковщик + упакованное главное меню ERS                                      | `source/mainmenu.a80` + `rom/mainmenu/main_pack.rom` |
| **`ROM_RST80`**    | **6** | `addon2.a80`                                                                    | `source/addon2.a80`                                  |
| **`ROM_RST81`**    | **7** | `addon1.a80` (обработчики, шрифты, дескрипторы меню, Perfect Cmd)               | `source/addon1.a80`                                  |
| **`ROM_RST82`**    | **8** | `addons.a80` (движок окон, печать, селектор меню, CMOS, мышь, файловый браузер) | `source/addons.a80`                                  |
| **`ROM_RST83`**    | **9** | `rst8service.a80` (диспетчер RST 8, драйверы, монтировщик, математика)          | `source/rst8service.a80`                             |
| `ROM_ADD_DOS`      | 10    | EVO‑DOS для эмуляции (в FE‑сборке не используется)                              | —                                                    |
| `ROM_ADD_BAS48`    | 11    | BASIC 48 (доп. копия)                                                           | —                                                    |
| `ROM_BAS48_STD`    | 0x18  | «чистый» BASIC 48                                                               | `rom/page3`                                          |
| `ROM_BAS128_STD`   | 0x19  | «чистый» BASIC 128                                                              | `rom/page2`                                          |
| `ROM_BAS48_128`    | 0x1A  | BASIC 48 из комплекта BASIC 128                                                 | `rom/page3`                                          |
| `ROM_ATMCPM`       | 0x1B  | ATM CP/M                                                                        | `rom/atm_cpm`                                        |

Важно: страницы идут в файле **в обратном порядке номеров**. `p2bin` пишет блоки в порядке эмиссии,
поэтому `rst8service.rom` = `[RST83][RST82][RST81][RST80][MAINMENU]`, а старшие адреса
512‑килобайтной микросхемы соответствуют младшим номерам страниц. Итоговая раскладка `ers_fe.rom`
(192 Кбайт, последние 12 страниц `zxevo_fe.rom`) собирается в `rom/build_full.sh`:

```
ff_16k | ff_16k | rst8service_fe(80K: RST83..MAINMENU) | ff_16k | basic48_128 | neo-dos | basic128 | services
```

### 1.2. Каждая страница заканчивается служебной записью

| Смещение  | Размер | Содержимое                                                         |
| --------- | ------ | ------------------------------------------------------------------ |
| `+0x3FF6` | 2      | свободное место в странице (`0xFF`, заполняется `FREE_*`)          |
| `+0x3FF8` | 6      | подпись страницы: `RST_08`, `ADDONS`, `ADDON1`, `ADDON2`, `MNMENU` |
| `+0x3FFE` | 2      | `DATA_VERS` — упакованная дата сборки                              |

Текущее состояние (по `rst8service.rom`):

| Страница | Подпись  | Свободно   |
| -------- | -------- | ---------- |
| RST83    | `RST_08` | 3280 байт  |
| RST82    | `ADDONS` | 438 байт   |
| RST81    | `ADDON1` | 2386 байт  |
| RST80    | `ADDON2` | 2437 байт  |
| MAINMENU | `MNMENU` | 1622 байта |

### 2.3. Страницы `ROM_RST81`, `ROM_RST80`

`addon1.a80` (`ROM_RST81`):

- заголовок: `JP CALL2PAGE` (0x0030), `PERFECTCOM` в поле `ADR_PERFECT` (0x0036),
  `JP INSTALL_NMIRST` (0x0040), распаковщик `UNPACK` (0x0080);
- `include rst8_data.a80` — **все дескрипторы окон/меню** (`MAIN_MENU`, `SETUP_MENU`,
  `FILESBROWSER`, `WIN_SEL_MOUNT`, `WIN_SEL_TRD`, легенда, тексты, таблицы горячих клавиш);
- таблица CRC16 и `CRC16_FAST` (используется инициализацией, CMOS, менеджером устройств);
- `INSTALL_NMIRST` — **главная точка инициализации сервиса** (см. §4);
- `FILL_MEM`, `SETUP_FONT`, `SET4RESETFONT`/`LD_SET_FONT` — загрузка шрифта из ПЗУ;
- `include nmi_service.a80` — код обработчиков RST 8/NMI (копируется в ОЗУ), отладчик, `CALL2PAGE`,

- `PERFECTCOM` — упакованный Perfect Commander (`perfpack_pack.bin`).

Дескрипторы из `rst8_data.a80` собираются с `PHASE $ + 0x4000`, поэтому адреса у них «окна 1»
(`MAIN_MENU = 0x4101`): меню рисуется при `WIN_A1 ← ROM_RST81`, а `LD IX,MAIN_MENU` даёт 0x4101.

`addon2.a80` (`ROM_RST80`):

- `UNPACK_STS` — распаковка отладочного монитора в `RAM_STS`;
- `UNP_MICRO_BOOT` — распаковка микрозагрузчика FAT (`fat_boot/micro_boot_fat_ers.pack`) в окно 3 и
  копия `BUF_CURRFATVAR` (используется RST 8 #0x54);
- `include fontread.a80` — `SCAN_FONT` (чтение текущего шрифта знакомест из ПЗУ);
- шрифты `CP866_FONT`, `ATM_FONT` (упакованные), `STS_PACK`.

### 2.4. Страница `ROM_MAINMENU` — `source/mainmenu.a80`

Страница‑контейнер: заголовок с `JP CALL2PAGE` (0x0030) и `JP UNP_MAINMENU` (0x0040), распаковщик в
0x0080 и `binclude` упакованного главного меню (`main_pack.rom` или `main_fe_pack.rom`). Вход —
адрес `0x0101` (`UNP_MAINMENU`), куда передаёт управление `rom/page0/source/services.a80`; `DE` =
адрес распаковки (0x6000), после распаковки управление уходит в ОЗУ. Само меню собирается в
`rom/mainmenu/src`.

## 3. Точки входа

### 3.1. Векторы страницы `ROM_RST83`

| Адрес    | Код                   | Назначение                                                      |
| -------- | --------------------- | --------------------------------------------------------------- |
| `0x0000` | `JP $`                | заглушка (страница никогда не стоит в окне 0 при работе)        |
| `0x0008` | `JP $`                | заглушка (вход `RST 8` — только через страницу `ROM_ERS`)       |
| `0x0010` | `JP $`                | заглушка                                                        |
| `0x0014` | `OUT (C),A; NOP; RET` | **`ADR_SEL_ROM`** — переключить страницу окна и вернуться       |
| `0x0020` | `JP CALL2RAMPAGE`     | вызов кода в другой странице ОЗУ                                |
| `0x0024` | `JP RST8PAGE0`        | вход `RST 8` с принудительным выбором страницы 0                |
| `0x002C` | `JP NEXT_RST8`        | **точка продолжения `RST 8`** (сюда приходит обработчик из ОЗУ) |
| `0x0030` | `JP CALL2PAGE`        | вызов кода в другой странице ПЗУ                                |
| `0x0034` | `JP CONT_MAGIC`       | продолжение обработки NMI                                       |
| `0x0038` | `EI; RET`             | прерывание                                                      |

| Адрес    | Страница | Что это                                                                                                              |

| `0x0040` | RST82    | `UNP_DOS_FE` — распаковка эмулятора ВГ в `CPU2` (только в `DOS_FE`-сборке)                                           |

### 3.3. `RST 0x30` — межстраничный вызов (`CALL2PAGE`)

```asm
        RST 0x30
        DW  <адрес подпрограммы в странице>
        DB  <номер страницы ПЗУ>
```

`CALL2PAGE` (в странице RST81, код работает в ОЗУ) сохраняет вызывающую страницу в стеке страниц
`STEK_PAGES`/`TEKPAGE`, включает нужную страницу в окно 0, вызывает адрес и восстанавливает
окружение по `RET`. Макрос — `ROMCALL` из `rom/macros.a80`. Аналогично `RST 0x20` (`RAMCALL`) —
вызов в другой странице ОЗУ.

## 4. Инициализация

Инициализация выполняется **при каждом сбросе** из стартовой страницы
(`rom/page0/source/services.a80`):

```asm
        PEC_ON M_SHADOW_BF
        LD HL,.L3               ; адрес возврата в page0
        PUSH HL
        LD HL,0x40              ; INSTALL_NMIRST
        PUSH HL
        LD BC,WIN_A0
        LD A,ROM_RST81
        JP ADR_SEL_ROM          ; окно 0 ← RST81, RET на 0x0040
.L3     ...
```

Далее `INSTALL_NMIRST` (`source/addon1.a80`) выполняет:

1. **Отвязка окна 3 от порта 7FFD** (`ATMPORT WIN_A3,0x40`) — чтобы адресация окна 3 не зависела от
   состояния `0x7FFD`.
2. **Страница переменных** в окно 2 (`WIN_P2 ← RAM_NMI`); по адресу `ADR_MAGIC` (0x8068)
   прописывается `JP NMI_SERVICE`.
3. **Сброс эмулятора ВГ**: в `FDD_EMU_PORT` пишется 0, `B_PORT_VIRT` обнуляется.
4. **Проверка целостности обработчика**: если клавиша `0` не нажата, считается CRC16 блока 0x40 байт
   в ОЗУ (`CPU2+STACK_NMI`) и сравнивается с CRC16 того же блока в ПЗУ (`CODE_NMIRST+STACK_NMI`).
   При совпадении дорогое копирование пропускается.
5. **Холодная установка** (CRC не совпал либо нажата `0`):
   - зачистка страниц `RAM_FATVARS`, `RAM_MOUNTER` и последней страницы ОЗУ (`FILL_MEM`, с
     сохранением ячейки `HDDTIMEOUT`);
   - копирование `CODE_NMIRST..ENMI_SERVICE` из ПЗУ в ОЗУ (`CPU2`, страница `RAM_NMI`) — обработчики
     `RST 8`/NMI живут в ОЗУ, потому что им нужно переключать страницы ПЗУ;
   - сброс CRC‑кэша таблицы разделов (`BUF_VOLUMES+0xFE`), `DEBUG_ONOFF=0`,
     `DEVMAN_VARS.FLAGS_DRV=0`, `FATVARSFLAGS=0`;
   - загрузка шрифта по CMOS (`CMOS.BYTE_00`, бит `M_TYPE_FONT`): ATM (KOI8) или CP866 в
     `RAM_SCR_FONT` по смещению `OFFSET_BUFSYM`;
   - `VIRT_BITS ← CMOS.VIRT_REAL_DRIVE` (при инициализации монтируется только рамдиск).
6. **`INIT_CMOS`** (страница RST82): подсчёт CRC16 ячеек `0xE9..0xED`, при несовпадении — запись
   дефолтов `CMOS_DEFAULT` и нового CRC.
7. **`SET4RESETFONT`**: если в CMOS не выставлен бит «не перезагружать шрифт» (`M_RELOAD_FONT`),
   шрифт из ПЗУ загружается в теневую страницу шрифтов (0x800 байт, при
   `PEC_ON M_SHADOW_BF+M_FONT_BF`).
8. **`RESTORE_FATVARS`**: восстановление буферов FAT «внешнего» софта.
9. **Определение HDD и задержка**: чтение статуса (`0x1F7`), таймаут из CMOS `HDD_TIMEOUT` (0..9 сек
   → `25 * n` тиков); значение хранится в `HDDTIMEOUT`. Если в ячейке `1` — задержка игнорируется
   (повторный сброс во время работы).
10. **Подготовка сервиса**: `TEKPAGE ← STEK_PAGES` (стек страниц для `RST 0x30`),
    `ADR_INT ← READ_KEYS` (по прерываниям опрашивается клавиатура), окно 0 возвращается на страницу
    `ROM_ERS`, `FOR_RET = 0`.

После этого `rom/page0` либо запускает главное меню, либо уходит в альтернативную прошивку (см.
`rom/page0/README.md`).

### 4.1. Горячий путь инициализации меню MAGIC

Отдельного «init» у меню нет: вход по NMI всегда идёт через `CONT_MAGIC` (`rst8service.a80`),
который каждый раз:

1. сохраняет регистры AY (`STORE_AY`);
2. проверяет флаги отладчика (`DEBUG_ONOFF`/`DEBUGGER.B_TRACE`) и при необходимости уходит в
   отладчик;
3. обрабатывает «бряк» (`N_BF`, `M_BREAK_BF`) — если сработало прерывание по адресу, подгружается
   TAP‑загрузчик (`MAINPAGE3_TAP` + `EMULOADTAP`);
4. сохраняет текстовый экран (`STORE_TXTMODE`), читает текущий шрифт (`SCAN_FONT`), палитру
   (`RD_SET_PAL`), подменяет шрифт на «магический» (`MAGIC_FONT`);
5. сохраняет переменные FAT внешнего софта (`STORE_FATVARS`);
6. чистит текстмод, печатает заголовок и **дамп портов/регистров** (`PRT_PORTREGS`), время/дату;
7. включает `WIN_A1 ← ROM_RST81`, строит окно `MAIN_MENU` (`SETUP4SEL` + `INT_TXT_WINDOW`) и
   передаёт управление селектору (`ITSELECTOR`) — тот не возвращается, пока пользователь не выйдет
   из меню; результат (`A`) трактуется как: 0 — полный выход в программу, 1 — перерисовать меню
   (BREAK), 2 — выход из отладчика, 3 — выход без восстановления экрана (см.
   `CONT_MAGIC2`/`CONTMAGIC3`).

При выходе восстанавливаются текстовый экран, шрифт, палитра и переменные FAT, затем
`EXITNMISERVICE` возвращает управление прерванной программе.

## 5. Анатомия вызова `RST 8`

1. `RST 8` переводит процессор на `0x0008`. Эта точка есть только в странице `ROM_ERS` (0x0008:
   `NOP; JP DOS2RST8`). DOS использует тот же стаб напрямую — макрос `RST8D` в `rom/page1/*`
   раскрывается в `CALL DOS2RST8` + байты параметров.
2. `DOS2RST8` (в `services.a80` — `0x3CF6`) формирует кадр возврата: сохраняет `HL`, `AF`, `BC`,
   `R`, адрес возврата, `DE`; читает текущие страницы и биты `RAMNROM`/`DOS7FFD`; затем переключает
   **окно 0 на страницу ОЗУ `RAM_NMI`** через `WIN_P0`.
3. Так как окно 0 подменилось «под ногами», выполнение продолжается по тому же адресу `0x0014` уже в
   копии из ОЗУ: `OUT (C),A; NOP; NOP; JP RAMSEL1`. (`FOR_RET` — «пятый байт», который патчится в
   `RET`, когда `0x0014` нужно использовать как `ADR_SEL_ROM`.)
4. `RAMSEL1` (ОЗУ, ~0x8018): сохраняет все регистры и альтернативный набор, читает теневые регистры
   конфигурации (`R_*`), обнуляет биты эмуляции ВГ, принудительно включает **7 МГц** и выключает
   турбо 14 МГц, отвязывает окно 3 от `7FFD`, включает `WIN_A0 ← ROM_RST83` и уходит на `CONT_RST8`
   (0x002C) → `NEXT_RST8`.
5. `NEXT_RST8`/`NEXT_RST` (в `ROM_RST83`):
   - читает байт‑параметр вызова из памяти вызывающего (`P5_READ_BYTE` — учитывает, в каком окне и в
     какой странице находится адрес возврата);
   - определяет видеорежим (`CMP_SCRMODE`) и адрес списка байтов маппера (`B1_CPU2`/`B0_CPU2`);
   - по номеру функции `(byte & 0x3F)` берёт адрес из `CODE_TABL` и передаёт управление.
6. Функция работает, при необходимости меняя «сохранённые» регистры вызывающего (`RREG_A..`,
   `RREG_IXL/IYL`, альтернативные) — именно они восстанавливаются на выходе.
7. Выход: `EXIT_RST8` → `P4_EXIT_RST8` (ОЗУ): восстановление теневых портов, AY, страницы эмуляции
   ВГ, стека; в стек кладётся `ADR_RST8END = 0x3CE8`, выбирается страница вызывающего, и `RET` с
   адреса `0x0014` этой страницы уходит на `0x3CE8` — в `EDOS2RST8`, который восстанавливает
   регистры и делает окончательный `RET` в точку после байтов параметров.

Итог: для софта `RST 8` полностью прозрачен (сохраняются все регистры, включая `IX/IY/AF'`, режим
прерываний и конфигурация портов), а параметры вызова читаются прямо из кода вызывающего.

### 5.1. Контракт страницы, в которой может выполняться `RST 8`

| Адрес    | Требование                                                                               |
| -------- | ---------------------------------------------------------------------------------------- |
| `0x0014` | `OUT (C),A; NOP; RET` (`ADR_SEL_ROM`)                                                    |
| `0x0008` | вход обработчика (`NOP; JP DOS2RST8`) или собственный эквивалент (`CALL DOS2RST8` в DOS) |
| `0x3CE8` | `EDOS2RST8` — восстановление регистров и возврат                                         |

## 7. Меню MAGIC (кнопка NMI) — `ROM_RST81`, `source/rst8_data.a80`

Меню строится селектором `selector.a80`; дескриптор окна — 20 байт по `IX` (см. комментарий в начале
`source/window.a80`). Окно рисуется на **текстовом** экране 80×25 (в отличие от главного меню ERS,
которое рисуется на ZX‑экране), мышь принудительно отключается (`ITSELECTOR` сбрасывает
`SYSFLAGS.B_MOUSE_PRESENT`).

Навигация: стрелки вверх/вниз (по пунктам), влево/вправо (первый/последний пункт), `SPACE`/`ENTER` —
выбор, хоткей — немедленный выбор, `BREAK` (`CS`+`SPACE`) — перерисовка меню.

### 7.1. Главное меню (`MAIN_MENU`, окно 0x04,0x04, 0x20×5)

Заголовок: `MAGIC Service`. Над меню печатается дамп регистров и конфигурации: `SP`, `PC`, `IR`,
`AF`/`AF'`, `BC`/`BC'`, `DE`/`DE'`, `HL`/`HL'`, `IX`, `IY`, `INT`, `IM`, `CPU3..CPU0` (по 2 байта
мапперов), `7FFD`, `EFF7`, `77`, `5F`, `BF`, `3F`, `1F`, `DOS`, `BREAK`, `TURBO`, а также
`EVO Magic Service vX.XX.XX`. В правом верхнем углу — время/дата из CMOS.

| Клавиша | Пункт            | Что делает                                                                                                                                                                                                                                              |
| ------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0`     | Continue program | `CONTINUE_PROG`: восстановить стек прерванной программы, вернуть `A=0` → вызывающий код дожидается отпускания клавиш, восстанавливает текстмод, шрифт, палитру, переменные FAT и через `EXITNMISERVICE` возвращает управление туда, где была нажата NMI |
| `S`     | Setup            | открыть подменю настроек (см. 7.2)                                                                                                                                                                                                                      |
| `F`     | File browser     | `FILE_BROWSER`: работа с FAT‑устройствами (см. 7.3). Если браузер уже открыт из главного меню ERS, пункт заблокирован (`SYSFLAGS.B_NMI_FB_BLOCK`) и внизу печатается «File Browser is blocked»                                                          |
| `D`     | Debugger STS     | есть только при `BUILD_DEBUG=1` (в текущей сборке `BUILD_DEBUG=0` — пункт отсутствует)                                                                                                                                                                  |

### 7.2. Setup (`SETUP_MENU`, окно 0x06,0x06)

Значения справа обновляются сразу после изменения (`SETUP4SEL` подставляет текст из `TXT_TURBO`,
`TXT_MEMORY`, `TXT_ONOFF`) и сохраняются в CMOS.

| Клавиша | Пункт              | Что делает                                                                                                                                                                                                                                       |
| ------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `0`     | Main menu          | `RESTART_MAIN` — вернуться в главное меню MAGIC с полной перерисовкой                                                                                                                                                                            |
| `W`     | Turbo              | `SET_TURBO`: циклически `7.0 → 3.5 → 14.0 МГц`; пишет CMOS `0xED` бит7 (`TURBO14`) и `0xEC` бит7 (`TURBO357`), обновляет `B_PORT77`/`N_EFF7`. Реально применится при выходе из меню (для вызывающей программы сохраняются её «теневые» значения) |
| `M`     | Memory             | `SET_MEMORY`: циклически `1 Мб → 48 К → 128 К`, пишет CMOS `0xEC` биты 1‑0                                                                                                                                                                       |
| `R`     | Resident Honey Cmd | `SET_REZIDENT`: вкл/выкл проверку резидента Honey Commander (CMOS `0xEC`, бит `M_REZIDENT`); резидент — код в странице `0x1F` верхней памяти, которому передаётся управление при сбросе (`rom/page0`, `CMP_REZIDENT`)                            |
| `K`     | Kill rezident      | `KILL_REZID`: вкл/выкл «порчу» резидента (CMOS `0xE8`, бит `M_KILL_REZIDENT`) — однократный запуск с последующей порчей кода                                                                                                                     |

### 7.3. Файловый браузер (`FILESBROWSER`) и его меню

Окно браузера занимает весь текстовый экран (`TXT.H_FILES`=60/32 × `TXT.V_FILES`=25/24, в
зависимости от сборки; 60×25 для ERS). В верхней строке — заголовок `File browser`, в последней —
подсказка `D.Drive select  ENTER.Select`, справа — окно‑легенда цветов:

| Цвет                   | Расширение         |
| ---------------------- | ------------------ |
| белый фон с ярко‑белым | каталог (`DIR`)    |
| зелёный                | `TRD`              |
| жёлтый                 | `SCL`, `FDI`       |
| красный                | `TAP`              |
| циан                   | прочее/неизвестное |

Как работает:

1. `DEVFIND` — поиск устройств и разделов (HDD Nemo/IDE, SD NeoGS, SD ZC). Если ничего нет — окно
   `Device not found` + любая клавиша → возврат в меню.
2. `FIND_FILEITEM` с маской расширений `TRD SCL FDI TAP` — сбор списка, затем `SORT_FINDFILES` —
   сортировка (каталоги первыми, затем по имени).
3. `TXT.V_FILES-2` строк выводятся из `RAM_SORTFILES`; имя — длинное (LFN), для 8.3
   обрезается/дополняется, при переполнении печатается `>`.
4. `ENTER` — вход в каталог или выбор файла; `D` — смена устройства/раздела; `BREAK`/`CS+1` — выход
   в меню.

Пункты окна (дескриптор `FILESBROWSER`): все видимые строки ведут в `SELECT_FILE`, последняя
служебная — в `SELECT_DRIVE`.

**Меню выбора устройства** (`SELECT_DRIVE`, строится на лету в `ENMI_SERVICE`): строки вида
`E.HDDNemo MAST:FAT32`, буква диска = `'E' + индекс`, тип раздела — `FAT12/FAT16/FAT32`. Хоткеи —
`e`, `f`, `g`… по числу найденных разделов; `ENTER` — выбрать (`SET_VOL`) и заново прочитать
каталог.

**Меню образа для `SCL`/`FDI`** (`WIN_SEL_MOUNT`, заголовок `Images`):

| Клавиша  | Пункт          | Что делает                                                                                                             |
| -------- | -------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `0`      | Only load      | `LOADIMAGES` — только распаковать образ в рамдиск, буквы дисководов не менять                                          |
| `1`..`4` | Ramdisk A:..D: | `TRD2RAMDISKx` — распаковать в рамдиск и переключить реальный/виртуальный дисковод на указанную букву (`SET_VIRTREAL`) |
| `X`      | Exit           | вернуться к списку файлов (`SEARCHFILES`)                                                                              |

**Меню образа для `TRD`** (`WIN_SEL_TRD`, заголовок `TRD to:`): то же плюс `5`..`8` — `MOUNT_A..D`
(`OPEN_MOUNT_INT` + `SET_VIRTREAL`) — примонтировать образ к букве без загрузки в рамдиск.

Особенности:

- `TAP` — принудительно включается бит `CMOS_ED.M_EMUL_TAPE` и файл загружается в память
  (`LOADIMAGE`), затем выход в меню;
- неудачная загрузка → окно `FDI image error` / `Device not found`;
- при переходе в главное меню ERS и обратно буферы FAT переключаются
  `STORE_FATVARS`/`RESTORE_FATVARS` (внутренние и внешние наборы переменных);
- при выходе из каталога вверх восстанавливается позиция курсора (`FATVARS.WINPOS`, до `64/3`
  уровней).

### 7.4. Прочие окна страницы

`DEV_NOTFOUND`, `NOFILES` (`Files or DIR not found`), `LDFDIERROR`, `SDCARD_LOST` («SD card lost /
Press RESET»), `LEGEND_EXT` (легенда цветов).

## 8. Главное меню ERS (страница `ROM_MAINMENU`)

Хотя исходники меню лежат в `rom/mainmenu/src`, его образ входит именно в этот сервисный блок (5‑я
страница) и является тем, что пользователь видит после сброса. Оно исполняется в ОЗУ с адреса
`0x6000`, рисуется на ZX‑экране (`S_FACE`), умеет работать с мышью.

### 8.1. Основные пункты (`MAINTXT`)

| Клавиша | Пункт       | Что делает                                                                                                                      |
| ------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `Z`     | TR-DOS boot | `GLUBOOT` — загрузчик с дискеты TR‑DOS (реальный/виртуальный дисковод, меню файлов дискеты)                                     |
| `F`     | File browse | `FILE_BROWSER` — файловый браузер FAT (аналог NMI‑браузера)                                                                     |
| `T`     | Tape load   | `TAPELOAD` — загрузка с магнитофонного входа или эмуляция `LOAD ""`                                                             |
| `B`     | HDD boot    | `HDD_BOOT` — старый загрузчик с винчестера                                                                                      |
| `D`     | CD boot     | `CDBOOT` — загрузчик с CD (наследие GLUK)                                                                                       |

## 9. Ключевые подсистемы

### 9.1. Менеджер устройств (`fat/dev_drv.a80`)

- Таблица `TABLDEV`: `DEVFIND`, `SET_VOL`, `KOL_VOL`, `GET_FNDVOLUME`, `TO_DRV`, `SET_DEVICE`,
  `CONTROL_SD`, `COMHDDNEX`, `FREINIT_VOL`, `SET_SECTOR_NUM`.
- Разбор MBR (4 записи по 16 байт с `0x01BE`), типы: `01`→FAT12, `04/06/0E`→FAT16, `0B/0C`→FAT32.
- Переменные — `DEVMAN_VARS` (в хвосте `BUF_VOLUMES`): список устройств (16), адрес драйвера,
  число/номер раздела, тип, `FLAGS_DRV`.
- Кэш результата поиска по CRC16 таблицы разделов (`BUF_VOLUMES+0xFE`, `CRC_SIZE=0xE0`).
- Драйверы: FDD A..D, HDD (Nemo/SMUC/Divide/Profi/Turbo2 Master+Slave), SD NeoGS, SD ZC, USB SL811
  (в таблицу не попадает при `USB_ENABLE=0`).
- `SET_DEVICE` — Master/Slave + LBA.

### 9.2. FAT (`fat/read_fat.a80`)

FAT12/16/32, BPB, цепочки кластеров, каталоги (до 16 уровней), открытие/последовательное чтение
файла, длинные имена (UTF‑16 → CP866 с перекодировкой `0x0401/0x0410..0x0451`), маска расширений,
сортировка списка. Сектор строго 512 байт (`_BPB_BytsPerSec == 0x200`), до 2048 найденных
файлов/каталогов. Подфункции `_POS_FILES` (0..7) — сохранение/восстановление позиции, перемотка,
подсчёт «легальных» записей, переход по номеру.

### 9.3. Монтировщик и рамдиск (`fat/mounter.a80`)

- `OPEN_MOUNT` — примонтировать образ к букве A..D (`BUF_MOUNTDRIVES`, 4×0x40 байт по
  `struct_mount.a80`); `FIND_MOUNTED` — разбор `IMAGE.MNT` (≤512 байт, строки
  `E:/путь/файл.ext a:`); `CLOSEMOUNT` — демонтирование; `RDWR_MOUNT` — чтение/запись секторов
  примонтированного файла; `GET_VIRT_BITS`/`SET_VIRTREAL`/`SET_REAL`/`SET_VIRT` — работа с битами
  `VIRT_BITS` (старшие биты — рамдиск, младшие — примонтированные диски) и запись
  `CMOS.VIRT_REAL_DRIVE`; `LOADIMAGE` — загрузка TRD/SCL/FDI/TAP в рамдиск.
- Рамдиск: формат, близкий к TRD. Начало — `RAM_RAMDISK` (страница 0x0A), данные — с `RAM_DATARAMD`
  (0x0B, 50 страниц). Признак форматирования — байты `"R"`/`"D"` по смещениям `+0x3FFF`/`+0x3EFF`
  первой страницы; иначе — принудительное форматирование на 2544 сектора. Описатели
  дорожек/секторов: `+0x000` смещение в блоках 256 байт, `+0x100` смещение в страницах, `+0x200`
  номер сектора, `+0x300` размер сектора ×2, далее шагом 0x100 следующий сектор, `+0x001` —
  следующая дорожка.

### 9.4. Математика (`math.a80`)

Подфункции `MATH`: `DIVIDE16` (`HL/DE`), `MULTIPLY16` (`HL*DE`), `DIVIDE32`, `MULTIPLY32`,
`HEX4DECTXT`, `HEX2DECTXT`, `HEX1DECTXT` (преобразование числа в ASCII‑строку в ОЗУ). Алгоритмы без
таблиц, только регистры + `RREG_*`.

### 9.5. Эмуляция магнитофона (`tape.a80`)

При включённом `CMOS_ED.M_EMUL_TAPE` вызов `TAPE_EMUL` копирует блок TAP из страниц `RAM_TAPE+n` в
адрес загрузки, обновляя «номер страницы» (0x8002) и «смещение» (0x8000); автоматически переключает
окно 2 с `0xFA` на `0xFD` при переходе через `0xC000`. Используется точкой перехвата `0x0556`
(эмуляция `LOAD ""`) и загрузчиком HOBETA.

### 9.6. Принтер через AY (`ay_printer.a80`)

Вывод в LPT через регистры AY (`0xFFFD`/`0xFFBF`): `AY_PRN_INIT` (последовательность `INTX`),
`AY_PRN_A_` (символ), `AY_PRN_TOKEN` (токен BASIC с раскрытием ключевых слов), `AY_PRN_SCR` (копия
экрана, `GRSET1/2/3`). Ожидание готовности — с опросом `BREAK_KEY`.

### 9.7. Окна и печать (`window.a80`)

Дескриптор окна (20 байт, адрес в `IX`):

| Смещение    | Поле                                                                                                     |
| ----------- | -------------------------------------------------------------------------------------------------------- |
| `+0`,`+1`   | X, Y (в знакоместах)                                                                                     |
| `+2`,`+3`   | высота (V), ширина (H)                                                                                   |
| `+4`        | цвет окна                                                                                                |
| `+5`        | цвет курсора                                                                                             |
| `+6`        | флаги (`DOWN_HEADER`, `WINFRAME`, `UPHEADER`, `TEXT`, `MENU_FILE`)                                       |
| `+7`        | флаг номера пункта: бит7 — текущий пункт хранится по адресу из `+8`, бит6 — количество по адресу из `+A` |
| `+8`,`+9`   | текущий пункт / адрес хранения                                                                           |
| `+A`,`+B`   | количество пунктов / адрес хранения                                                                      |
| `+C`,`+D`   | адрес текста                                                                                             |
| `+E`,`+F`   | адрес таблицы подпрограмм пунктов                                                                        |
| `+10`,`+11` | адрес списка зон для мыши                                                                                |
| `+12`,`+13` | адрес списка горячих клавиш                                                                              |

Тот же движок печатает строки с управляющими кодами: `\r` — перевод строки в окне, `\x16 x y` —
позиционирование, `\x17 цвет` — цвет, `\x01`/`\x02`/`\x03` — пауза/вставка (см. реализацию
`PRINT`/`IPRINT_MESSAGE`), `\x00` — конец. Для ZX‑экрана — `WINW_ZX`/`PRINT` с побайтовой адресацией
через таблицы `BUFTSC`/`TBUFTSC*` (`addons.a80`).

### 9.8. Селектор меню (`selector.a80`)

`ITSELECTOR` (текстовый режим, без мыши) / `ISELECTOR` (ZX‑экран, с мышью) → `SELECTOR`: опрос мыши
(`MOUSE`, `MOUOPT`), клавиатуры (`KEYBOARD` через прерывания — `ADR_INT ← KEYBOARDS`), время
(`PRINTTIME`), `BREAK` (`BREAK_KEY`), поиск нажатой клавиши в таблице окна (`CPIR` по `+12`/`+13`),
вызов подпрограммы пункта и «раскраска» курсора (`COLOR_CURSOR`/`SET_ADR_ATR`). Выходы:
`CONTINUE_PROG` (A=0), `RESTART_MAIN` (A=1), `TRACER_DBG` (A=2).

### 9.9. Шрифты

- из ПЗУ: `ATM_FONT` (KOI8) или `CP866_FONT` — выбор битом `CMOS_ED.M_TYPE_FONT`;
- при входе в MAGIC: `MAGIC_FONT` добавляет служебные символы (`SYM00..SYM07` из `window.a80`) по
  смещению `0xF2*8` и включает их (`PEC_ON M_SHADOW_BF+M_FONT_BF`);
- `RESTORE_FONT` возвращает сохранённый шрифт (`RAM_SCR_FONT`, смещение `OFFSET_FNTSAVE`);
- `SCAN_FONT` (RST80) — считывание текущего шрифта с экрана ПЗУ;
- пользовательский шрифт — `SETUP_FONT` (RST 8 #0x57) или файл `*.FNT` из файлового браузера.

### 9.10. CMOS (`call_cmos.a80`)

`INIT_CMOS` — проверка CRC16 ячеек `0xE9..0xED` (CRC лежит в `0xEE`/`0xEF`), при ошибке —
`CLEAR_CMOS` (запись `CMOS_DEFAULT`). Любая запись (`IWRITECMOS`/`EWRITE_CMOS`) пересчитывает CRC.
Дефолты: `04 82 00 00 00 00 00` для `0xED..0xE7`.

## 11. Сборка

```bash
cd rom/page5/source
./build.sh          # из rom/ — source build.sh (нужны ASL и mhmt)
```

`build.sh`:

1. `mhmt -mlz` упаковывает `8x8_ar.fnt`, `866_code.fnt`, `atm_code.fnt`, `perfpack.bin` в
   `*_pack.bin`;
2. два прохода `asl`: обычный и с `-D DOS_FE` (вариант с аппаратной эмуляцией ВГ);
3. `p2bin … -r '$-$'` → `../rst8service.rom`, `../rst8service_fe.rom` (80 Кбайт).

Крупная сборка — `rom/build_full.sh`: собирает все страницы и склеивает `ers_fe.rom` (192 К) →
`zxevo_fe.rom` (512 К).

Особенности:

- `USB_ENABLE EQU 0` в `rst8service.a80` — USB‑драйвер не задействован;
- `source/fat/fat_boot.a80` в сборку **не входит** (используется
  `../../fat_boot/micro_boot_fat_ers.pack`);
- `_CMP_FONT EQU 0` — проверка считанного шрифта отключена (ветки `IF _CMP_FONT` не собираются);
- `BUILD_DEBUG EQU 0` в `rom/macros.a80` — отладчик STS и пункт `D.Debugger` в меню отсутствуют.

## 12. Ограничения и подводные камни

- `RST 8` работает только когда окно 0 указывает на страницу с нужными стабами (`ROM_ERS`; DOS
  вызывает тот же стаб напрямую) — см. §5.1.
- Номер функции маскируется `AND 0x3F`, поэтому валидны байты `0x40..0x7F`; байты подфункций
  читаются из кода вызывающего, т.е. код должен находиться в доступной памяти.
- В сервисе принудительно включается 7 МГц и отключается 14 МГц; после выхода настройки
  восстанавливаются из сохранённых теневых регистров.
- Окно 3 на время работы отвязывается от `0x7FFD` (пишется `0x40` в `WIN_A3`).
- Мышь в меню MAGIC отключена (текстовый режим); в главном меню ERS — работает.
- Файловый браузер из MAGIC блокируется, если он уже открыт в главном меню ERS.
- FAT: только сектор 512 байт, только первичные разделы, ≤2048 файлов в каталоге, ≤16 уровней
  вложенности, `IMAGE.MNT` ≤512 байт, образов на буквы A..D — до 4.
- После смены/извлечения SD‑карты обязателен сброс — инициализация FAT выполняется при сбросе.
- Примонтированный образ имеет приоритет над рамдиском при совпадении буквы дисковода;
  демонтирование — `Service → Dismount image`.
