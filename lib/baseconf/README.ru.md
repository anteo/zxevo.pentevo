# BaseConf

`lib/baseconf` — библиотека на C и Z80 assembler для приложений ZX Evolution, работающих с
FPGA-профилем BaseConf. Она объединяет доступ к карте памяти и портам BaseConf с видеорежимами,
графикой, текстом, вводом, RTC/AVR, звуком, накопителями и выбранными интерфейсами ERS/прерываний.
Для PT3-модулей доступна обёртка над плеером Vortex Tracker II из z88dk: модуль должен оставаться
доступен в памяти, а приложение вызывает плеер с постоянной частотой.

Публичные заголовки находятся в `lib/baseconf/include/`. Библиотека использует обычную модель
связывания z88dk: в программу попадают только нужные члены архива. Она не заменяет CRT или системную
среду приложения, но поставляет целевую конфигурацию и локальный CRT-хук для консоли BaseConf.

## Требования и сборка

Нужны z88dk с компилятором SDCC и classic library, а также `zcc` и `z88dk-z80asm`. Из корня
репозитория соберите архив:

```sh
make -C lib/baseconf
```

Результат — `lib/baseconf/build/default/baseconf.lib`. Если инструменты установлены не в стандартном
месте, передайте `ZCC` и `Z80ASM`; переменные `Z88DK_ROOT`, `Z88DK_SRC` и `ZCCCFG` используются
проектной сборкой для доступа к z88dk.

## Подключение к приложению

Добавьте общий make-файл библиотеки в Makefile приложения. Он задаёт абсолютный путь к целевой
конфигурации, заголовкам и архиву, а также согласованные ABI флаги:

```make
ZCC ?= zcc
Z80ASM ?= z88dk-z80asm
include ../lib/baseconf/baseconf.mk

APP_FLAGS := +$(BASECONF_CFG) $(BASECONF_ABI_FLAGS) \
             -I$(BASECONF_INCLUDE) -L$(BASECONF_BUILD)
```

При сборке приложения используйте эти флаги и свяжите `baseconf` (например, `-lbaseconf`). Путь
`include` в примере нужно скорректировать относительно каталога приложения. Конфигурация BaseConf
опирается на штатный каталог конфигураций z88dk (`ZCCCFG`), чтобы найти стандартные заголовки и
библиотеки. Для прямого вызова `zcc` задайте `BASECONF_ROOT` как абсолютный путь к `lib/baseconf` и
выберите `+<абсолютный-путь>/config/baseconf.cfg`.

Основные настройки сборки библиотеки:

- `BASECONF_VIDEO_TEXT_MODES` и `BASECONF_VIDEO_PRIMITIVE_MODES` принимают `ALL`, `GRAPHICS`, `NONE`
  или список режимов;
- `BASECONF_CONSOLE_NO_DEFAULT_FONT=1` исключает font8, если приложение использует другой шрифт.

После изменения списка режимов или настройки шрифта пересоберите архив и перелинкуйте приложение с
ним.

## Размер приложения

`baseconf.lib` — архив, а не единый объект, который целиком копируется в программу. Линкер
подключает объекты, на чьи символы ссылается приложение, и их зависимости. Неиспользуемые API и
режимные реализации обычно не попадают в итоговый образ; один объект может содержать несколько
связанных функций, а одна функция может подтянуть общие вспомогательные объекты. Размер зависит от
набора вызовов и компоновки приложения, поэтому точный результат определяется картой линковки.

- **`CRT_ENABLE_STDIO`** задаётся для приложения, например `-pragma-define:CRT_ENABLE_STDIO=0`.
  Значение `1` оставляет стандартный stdio z88dk, включая привычный `printf` и связанные потоки; это
  удобно, но может заметно увеличить приложение. Значение `0` отключает стандартный stdio и generic
  console hook в CRT BaseConf, поэтому обычные `printf`/`scanf` использовать нельзя. Прямые функции
  BaseConf при этом доступны. Для компактного вывода можно использовать независимый от stdio
  `bc_printf()`, а для прямого вывода — `bc_console_putc()`, `bc_console_gotoxy()`,
  `bc_console_clear()` либо `bc_text_putc()`, `bc_text_puts()`, `bc_text_gotoxy()` и
  `bc_text_clear()` в аппаратных текстовых режимах.
- **`BASECONF_VIDEO_TEXT_MODES`** выбирает режимные реализации текстового и консольного вывода,
  которые попадут в библиотеку. Допустимы `ALL`, `GRAPHICS`, `NONE` или список режимов (`ZX_256`,
  `ATM_640`, `ATM_TEXT_80` и т. п.). Оставляйте только режимы, в которых приложение выводит текст.
- **`BASECONF_VIDEO_PRIMITIVE_MODES`** аналогично ограничивает режимные реализации графических
  примитивов. Для него `GRAPHICS` означает пять графических режимов; режимы 80×25 не добавляют
  графический primitive backend. Если нужны только отдельные режимы, укажите их явно.
- **`BASECONF_CONSOLE_NO_DEFAULT_FONT=1`** убирает автоматическую ссылку консоли на встроенный
  font8. Это не запрещает приложению явно использовать font8, но без такой ссылки шрифт не будет
  подтянут линкером только ради значения по умолчанию. В графических режимах задайте свой шрифт
  через `bc_console_set_font()` до вывода текста.
- **Графические примитивы:** если приложению нужны отдельные линии, окружности, эллипсы или
  горизонтальные/вертикальные отрезки, используйте прямые `bc_draw_*` функции. Варианты
  SET/CLEAR/XOR и функции с явной операцией — отдельные точки входа; вызывайте только нужные, чтобы
  не тянуть лишние archive members. Несколько ASM-функций могут быть сгруппированы в одном member,
  который подтянется целиком. Общий классический интерфейс z88dk (`plot`, `draw`, `circle` и другие)
  удобен для переносимого кода, но его обвязка и связанные функции также могут увеличить образ.

Пример сборки библиотеки только с нужными режимами:

```sh
make -C lib/baseconf \
  BASECONF_VIDEO_TEXT_MODES="ZX_256 ATM_TEXT_80" \
  BASECONF_VIDEO_PRIMITIVE_MODES="ZX_256" \
  BASECONF_CONSOLE_NO_DEFAULT_FONT=1
```

Настройки режимов и шрифта влияют на состав `baseconf.lib`; `CRT_ENABLE_STDIO` задаётся отдельно при
сборке приложения. Приложение должно использовать архив, собранный с нужными ему режимами. Эти
параметры в основном сокращают код и константные данные приложения; они не заменяют планирование RAM
под DATA/BSS и стек.

Для просмотра карты собранного приложения используйте утилиту:

```sh
python3 lib/baseconf/tools/memory_map.py path/to/application.map
python3 lib/baseconf/tools/memory_map.py path/to/application.map --sort size --name-width 36
```

Она показывает диапазоны и размеры областей памяти, модулей и функций, а также исходные файлы и
строки. Конечная граница диапазона не включается в него; границы функций определяются по следующему
символу функции в карте линковки. Имена в таблице обрезаются по ширине колонки (48 символов по
умолчанию; ширина задаётся через `--name-width`). `--sort size` сортирует области, модули и функции
по убыванию размера; без параметра используется порядок адресов. Алиасы могут иметь один диапазон, а
безымянные байты учитываются в ближайшем диапазоне.

## Инициализация и настройка

Вызовите `bc_init()` после запуска приложения и до использования высокоуровневых возможностей
библиотеки. По умолчанию используется профиль сервисного ROM ERS. Инициализация подготавливает
внутреннее состояние, но не настраивает карты и размещение памяти за приложение.

Приложение отвечает за карты памяти и поверхности экрана. Рядом с инициализацией можно настроить
профиль ERS через `bc_ers_set_profile()`, задать свою маску закреплённых окон через
`bc_set_pinned_windows()` или сообщить о подготовке карт через `bc_set_maps_prepared()`. По
умолчанию маска окон с кодом, DATA/BSS и текущим стеком вычисляется автоматически. Управление
менеджером страниц доступно через `bc_set_page_manager_enabled()`; оно учитывает флаг подготовленных
карт. Страницы рисования должны быть отображены как доступная для записи RAM в окнах W1–W3. Обычные
операции рисования не переназначают окна и не снимают защиту памяти.

```c
if (bc_init() != BC_OK) return 1;
```

Если приложению нужен менеджер страниц, настройте обе карты и закрепите все окна, которые должны
оставаться доступными. После этого сообщите библиотеке о готовности карт.

```c
bc_set_maps_prepared(1);
if (bc_set_page_manager_enabled(1) != BC_OK) return 1;
```

## Реализованные интерфейсы

Примеры ниже — фрагменты для приложения с `#include <baseconf.h>` и выполненным `bc_init()`. Каждый
фрагмент показывает отдельный сценарий. Условия работы с памятью и требования к профилю сборки
указаны рядом с примерами.

### Память и банки

`bc_get_active_map()` возвращает текущую карту, `bc_configure_window()` настраивает окно выбранной
карты, а `bc_window_acquire()` временно заменяет отображение. Завершайте успешный захват вызовом
`bc_window_release()`. Библиотека умеет отображать RAM и банки Flash и управлять защитой окна от
записи. [memory.h](include/baseconf/memory.h)

Обычная куча z88dk (`malloc`, `calloc`, `realloc`, `free`) по умолчанию не инициализируется: так
приложения без динамического выделения памяти не получают лишний код запуска. Чтобы включить кучу
между концом BSS и текущим стеком, задайте положительный резерв стека:

```c
#pragma output CRT_STACK_SIZE = 512
```

В этом режиме `malloc` использует свободный непрерывный диапазон от конца BSS до адреса
`SP - CRT_STACK_SIZE`. Число `512` — резерв под стек, а не защита от его переполнения; подберите его
под приложение. Этот механизм работает только с RAM, которая постоянно доступна по этому диапазону
адресов. Он не выделяет физические банки и не переключает окна BaseConf.

Пул `bc_ram_page_pool_t` охватывает физические страницы RAM `0..63` размером 16 КиБ.
Каждый бит восьмибайтовой маски включает соответствующую страницу. Например, чтобы исключить
страницы 2 и 5, первый байт маски равен `0xDB`,
остальные — `0xFF`. Пул не определяет занятые приложением или системой страницы, не очищает их и не
отображает в окна: маску нужно составить по раскладке приложения. Состояние выделения хранится
внутри `bc_ram_page_pool_t`. Полученную страницу можно временно подключить через
`bc_window_acquire()` и вернуть через `bc_window_release()`, а затем освободить в пуле через
`bc_ram_page_free()`.

Для размещения объектов поверх пула используйте `bc_ram_heap_t`. Она берёт страницы из пула по мере
заполнения предыдущих и использует classic z88dk именованные кучи внутри страниц. Аллокация
возвращает `bc_ram_heap_ptr_t` — пару «страница + смещение», а не обычный указатель. Перед чтением
или записью вызовите `bc_ram_heap_map()`, после работы — `bc_ram_heap_unmap()`. Пока отображение
открыто, указатель действителен только в выбранном окне; одновременно активен один lease. Объект
кучи, массив `bc_ram_heap_page_t`, маска и объект пула должны оставаться доступны в закреплённой
памяти, вне окна, которое куча переключает. Вызов `bc_ram_heap_destroy()` возвращает все страницы
пулу и делает все ссылки этой кучи недействительными.

```c
static const bc_ram_page_mask_t page_mask = {
    0xDB, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF
};
static bc_ram_page_pool_t pool;

bc_ram_heap_t heap;
bc_ram_heap_page_t heap_pages[4];
bc_ram_heap_ptr_t item;
void *address;

/* Страницы 2 и 5 исключены; проверьте остальные по раскладке приложения. */
if (bc_ram_page_pool_init(&pool, page_mask) != BC_OK ||
    bc_ram_heap_init(&heap, &pool, heap_pages, 4, BC_WINDOW_2) != BC_OK ||
    bc_ram_heap_alloc(&heap, 128, &item) != BC_OK) {
    return 1;
}

if (bc_ram_heap_map(&heap, item, &address) != BC_OK) return 1;
((uint8_t *)address)[0] = 42;
if (bc_ram_heap_unmap(&heap) != BC_OK) return 1;

if (bc_ram_heap_free(&heap, item) != BC_OK) return 1;
if (bc_ram_heap_destroy(&heap) != BC_OK) return 1;
```

Программирование Flash не реализовано.

### Видеорежимы и графика

Библиотека поддерживает ZX 256, ZX Multicolor, Pentagon 16 цветов, ATM 320 и ATM 640, а также
аппаратные текстовые режимы ATM и Evo 80×25. Режимы вывода и графические примитивы включаются
настройками сборки. Графический API рисует линии, окружности и эллипсы с операциями SET, CLEAR и
XOR. `bc_read_pixel_index()` читает пиксель выбранной поверхности.

Для смены видеорежима подготовьте карты и включите менеджер страниц, как описано выше.
`bc_set_video_mode()` подбирает отображение экранных страниц в незакреплённых окнах. Пример очищает
текущий видимый экран и рисует на нём в режиме ZX 256.

```c
if (bc_set_video_mode(BC_VIDEO_ZX_256) != BC_OK) return 1;
bc_set_ink(7);
bc_set_paper(0);
if (bc_console_clear() != BC_OK) return 1;
if (bc_graphics_begin() != BC_OK) return 1;
bc_draw_line(16, 16, 96, 64);
bc_draw_circle(96, 64, 16);
if (bc_graphics_end() != BC_OK) return 1;
```

Для двойной буферизации заранее отобразите страницы обоих экранов как доступную для записи RAM.
`bc_select_draw_screen()` выбирает, куда рисовать, а `bc_show_screen()` переключает видимый экран. В
режиме ZX графические примитивы меняют битовую карту, сохраняя атрибуты.
[video.h](include/baseconf/video.h) · [graphics.h](include/baseconf/graphics.h)

В classic z88dk подключите `#include <games.h>` для вывода программных спрайтов через `putsprite()`,
сохранения и восстановления фона через `bksave()` и `bkrestore()`, а также опроса джойстика через
`joystick()`. Реализация `putsprite()` для ZX работает со стандартной битовой картой по адресу
`0x4000`. Для неё отобразите нужную страницу экрана в W1 и держите код процедуры в доступной для
записи RAM. [games.h в z88dk](https://github.com/z88dk/z88dk/blob/master/include/games.h)

### Текст, шрифты и палитры

`bc_console_*` выводит текст с курсором как в графике, так и в режимах 80×25. Для графики можно
выбрать встроенный шрифт 8×8 или 5×7, либо передать собственный дескриптор через
`bc_console_set_font()`. Для аппаратного текста есть `bc_text_puts()`, а `bc_printf()` форматирует
строки и 16-битные целые без зависимости от stdio. Пример использует режим Evo 80×25 и включённый в
сборку текстовый вывод для него.

```c
if (bc_set_video_mode(BC_VIDEO_EVO_TEXT_80) != BC_OK) return 1;
bc_set_ink(7);
bc_set_paper(0);
if (bc_text_clear() != BC_OK) return 1;
if (bc_text_gotoxy(2, 1) != BC_OK) return 1;
if (bc_printf("Screen: %u x %u", bc_video_width(), bc_video_height()) < 0) return 1;
```

Аппаратный шрифт загружается из таблицы в 2 КиБ через `bc_upload_font_to()` или
`bc_upload_font_preserving()`. Палитра ULAplus в режимах ZX адресуется по индексу через
`bc_set_ulaplus_palette()`. Пример задаёт цвет для индекса 3 в активном режиме ZX.

```c
if (bc_set_ulaplus_palette(3, 0x9e) != BC_OK) return 1;
bc_set_ulaplus_enabled(1);
```

Запись ATM RGB222/RGB444 выбирает цвет по текущему положению луча, поэтому приложение синхронизирует
запись с растром. [console.h](include/baseconf/console.h) · [text.h](include/baseconf/text.h) ·
[printf.h](include/baseconf/printf.h) · [font.h](include/baseconf/font.h) ·
[palette.h](include/baseconf/palette.h)

### Мышь и клавиатура

Для клавиатуры ZX подключите `#include <input.h>` из classic z88dk. `in_Inkey()` опрашивает
клавиатуру и возвращает ASCII-код, а `in_LookupKey()` и `in_KeyPressed()` позволяют проверить
конкретную клавишу или комбинацию.
[input.h в z88dk](https://github.com/z88dk/z88dk/blob/master/include/input.h)

Kempston возвращает счётчики мыши и маску кнопок. `bc_mouse_delta()` учитывает переполнение
счётчиков. Сохраняйте предыдущий снимок между опросами и опрашивайте мышь достаточно часто, чтобы
перемещение помещалось в знаковую разность.

```c
bc_mouse_snapshot_t previous, current;
if (bc_mouse_read(&previous) != BC_OK) return 1;
/* При следующем опросе: */
if (bc_mouse_read(&current) != BC_OK) return 1;
bc_mouse_delta_t motion = bc_mouse_delta(&previous, &current);
previous = current;
```

PS/2 API читает физические модификаторы и сырые скан-коды из журнала AVR. Перед чтением журнала
установите известное окно через `bc_avr_window_select()`. После `BC_OK` проверяйте
`BC_PS2_SCANCODE_EMPTY` и `BC_PS2_SCANCODE_OVERFLOW`.

```c
uint8_t code;
if (bc_avr_window_select(BC_AVR_WINDOW_MODES) != BC_OK) return 1;
if (bc_ps2_scancode_read(&code) != BC_OK) return 1;
if (code != BC_PS2_SCANCODE_EMPTY && code != BC_PS2_SCANCODE_OVERFLOW) {
    /* Передайте байт декодеру скан-кодов приложения. */
}
```

[input.h](include/baseconf/input.h) · [ps2.h](include/baseconf/ps2.h)

### RTC, AVR и тайминг

RTC API читает дату и время в двоичном формате или BCD и даёт доступ к регистрам часов и NVRAM.
Через окно расширения AVR доступны метаданные прошивки, настройки видеовыхода и EEPROM. Выбор окна
должен оставаться стабильным во время операции, в том числе в обработчике NMI. `bc_frame_period()`
возвращает номинальную длительность кадра в тактах 3,5 МГц независимо от выбранной скорости CPU.

```c
bc_datetime_t now;
uint32_t frame_tstates;
if (bc_rtc_read_datetime(&now, BC_RTC_BINARY) != BC_OK) return 1;
if (bc_avr_window_select(BC_AVR_WINDOW_MODES) != BC_OK) return 1;
if (bc_frame_period(&frame_tstates) != BC_OK) return 1;
```

`bc_set_cpu_speed()` выбирает 3,5, 7 или 14 МГц. Для управления прерываниями доступны сохранение и
восстановление INT, запрос NMI, ловушка исполнения и операции newirq для маски, статуса и
подтверждения источников. Обработчики устанавливает приложение. [rtc.h](include/baseconf/rtc.h) ·
[timing.h](include/baseconf/timing.h) · [interrupt.h](include/baseconf/interrupt.h) ·
[newirq.h](include/baseconf/newirq.h)

### UART

UART API задаёт формат кадра и делитель, читает состояние линии и модема, отправляет и принимает
байты. Пример настраивает 8N1 с делителем 1 и ждёт байт не более 4096 опросов. Настройте другую
сторону соединения на те же параметры. Исчерпание бюджета возвращает `BC_BUSY`.

```c
const bc_uart_config_t config = {BC_UART_BITS_8, BC_UART_PARITY_NONE, 1, 1};
uint8_t byte;
if (bc_uart_configure(&config) != BC_OK) return 1;
bc_status_t received = bc_uart_wait_receive_polls(&byte, 4096);
```

[uart.h](include/baseconf/uart.h)

### Звук

В classic z88dk заголовок `#include <sound.h>` даёт функции бипера (`bit_beep()`, `bit_fx()`) и
проигрывание простых мелодий на AY через `psg_play()`. Для управления тонами, громкостью и
регистрами AY подключите `#include <psg.h>`.
[sound.h в z88dk](https://github.com/z88dk/z88dk/blob/master/include/sound.h) ·
[psg.h в z88dk](https://github.com/z88dk/z88dk/blob/master/include/psg.h)

`bc_covox_play()` блокирующе воспроизводит упакованные 4-битные сэмплы, начиная со старшей половины
байта. Для AY библиотека оборачивает PT3-плеер z88dk. Модуль должен оставаться доступен в памяти, а
приложение вызывает `bc_pt3_play()` один раз за музыкальный тик. Пример подходит для модуля с одним
тиком на кадр, если CPU просыпается от кадрового INT.

```c
extern const uint8_t music_pt3[];
uint16_t frame;
if (bc_pt3_init(music_pt3) != BC_OK) return 1;
bc_pt3_start();
for (frame = 0; frame < 250; ++frame) {
    if (bc_wait_frame() != BC_OK) break;
    bc_pt3_play();
}
bc_pt3_stop();
```

[audio.h](include/baseconf/audio.h)

### Прямой доступ к накопителям

`baseconf/storage.h` — низкоуровневый интерфейс контроллеров Nemo IDE, SD SPI и ВГ93. Операции с
512-байтными секторами IDE и SD выполняют команды контроллера напрямую. Выбор тома в ERS на них не
влияет. Для ВГ93 доступны выбор дисковода, системный порт, регистры контроллера и маска аппаратного
перехвата.

Nemo IDE поддерживает LBA28 для устройства 0, IDENTIFY и сброс кэша записи. Этот пример читает
первый сектор диска. Бюджет задан в опросах статуса ATA.

```c
static uint8_t sector[512];
if (bc_ide_read_sector(0, sector, 60000u) != BC_OK) return 1;
```

Для SD сначала определите тип адресации. `bc_sd_load()` дополнительно читает CID и CSD, а
`bc_sd_sector_count()` извлекает ёмкость из CSD. Контроллер FPGA использует фиксированную частоту
SPI. Бюджет чтения задан в байтах SPI, бюджет инициализации — в попытках.

```c
static uint8_t sector[512];
bc_sd_card_type_t card;
if (bc_sd_init(&card, 2000) != BC_OK) return 1;
if (bc_sd_read_sector(card, 0, sector, 60000u) != BC_OK) return 1;
```

Для чтения регистра статуса ВГ93 исключите NMI и оставьте маску FE-перехвата нулевой. При чтении
`BC_FDD_COMMAND` возвращается статус контроллера.

```c
uint8_t fdd_status;
if (bc_fdd_reg_read(BC_FDD_COMMAND, &fdd_status) != BC_OK) return 1;
```

По назначению этот слой соответствует `sdcard.h` и `diskio` из z88dk. Для собственных команд есть
API слов, блоков и SPI-транзакций. Поля CSD извлекает `extract_bits` из z88dk. Тест SD в ZEsarUX
покрывает команды, токены и блоки. Для проверки полной инициализации и освобождения busy после
записи нужна модель карты, которая воспроизводит эти фазы. [storage.h](include/baseconf/storage.h)

### Сервисы ПЗУ ERS

ERS уже предоставляет доступ к накопителям через ПЗУ. Менеджер устройств и функции FAT работают с
поддерживаемыми томами HDD и SD, а монтировщик управляет дисководами и образами дискет. Есть также
обёртки для версии ROM, окон и текста ERS, шрифтов и палитры, CMOS, ленты, принтера и арифметики.
Приложение должно подготовить ROM, RAM и состояние BASIC для `RST 08h`. Обёртки возвращают результат
вызова, а операции с накопителями дополнительно возвращают статус самой прошивки.

Пример открывает файл в корне FAT-раздела, выбранного ERS при обнаружении устройств.

```c
static const char name[16] = "README.TXT";
bc_ers_device_info_t volume;
bc_ers_fat_search_result_t file;
if (bc_ers_device_find(&volume) != BC_OK || !volume.found) return 1;
if (bc_ers_device_set_volume(volume.current_partition) != BC_OK) return 1;
if (bc_ers_fat_root_directory() != BC_OK) return 1;
if (bc_ers_fat_find_short_name(name, &file) != BC_OK || file.not_found) return 1;
if (bc_ers_fat_open_file() != BC_OK) return 1;
```

## Тесты и примеры

Тест-сьют находится в `lib/baseconf/tests/`. Он собирает кейсы и запускает их в ZEsarUX с поддержкой
BaseConf; подробности, устройство кейсов и способы запуска описаны в `lib/baseconf/tests/README.md`.
Основная команда запуска — `make -C lib/baseconf/tests test`.

Небольшие примеры использования библиотечных интерфейсов находятся в `lib/baseconf/tests/cases/`.
Это тестовые программы, а не отдельный набор прикладных примеров.

## Основные заголовки

- `baseconf.h`, `baseconf/memory.h` — инициализация, память и карты.
- `baseconf/video.h`, `graphics.h`, `text.h`, `console.h`, `printf.h`, `palette.h`, `font.h` —
  видеорежимы и вывод.
- `baseconf/input.h` — мышь Kempston.
- `baseconf/ps2.h`, `audio.h`, `uart.h` — PS/2, звук и последовательный порт.
- `baseconf/rtc.h`, `timing.h`, `interrupt.h`, `newirq.h` — RTC/AVR, тайминг и прерывания.
- `baseconf/storage.h`, `rom.h`, `ers.h` — прямой доступ к накопителям и сервисы ПЗУ.
